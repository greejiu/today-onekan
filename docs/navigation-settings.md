# 사용자별 탭 설정

기준 main: `790055b3632f7dbc4b648e50e766efa5e85fca01`.

설정의 **탭 설정**에서 표시 여부와 순서를 변경한다. 표시된 메뉴를 순서대로 세어 앞쪽 5개를 데스크톱 아이콘 레일과 모바일 하단바에 표시하고, 나머지는 더보기에서 표시한다. 설정은 항상 더보기의 마지막이며 숨길 수 없다. 숨김은 네비게이션에만 적용하고 페이지와 데이터를 유지한다. 현재 페이지가 숨겨지면 지금한칸으로 이동한다. 지금한칸도 숨겨졌을 경우 페이지 자체는 안전한 이동 대상으로 유지한다.

기본 순서: 지금한칸, 일정, 할일, 습관, 기록, 목표, 추적, 같이한칸, 커뮤니티, 모두. 최초에는 모두 표시한다. 기존 사용자에게도 저장된 탭 설정이 없으면 이 기본값을 사용하며, 첫 변경 시 저장한다.

- `assets/navigation.js`: 메뉴 registry, 설정 정규화, 모바일/더보기/설정 목록, 사용자별 읽기와 부분 upsert.
- `assets/todo-sidebar.js`: 같은 registry를 이용하는 데스크톱 레일. 기존 접기·펼치기, 세부 메뉴, 할일 그룹 이동을 유지한다.
- `assets/navigation.css`: 설정 행, 드래그 피드백, 모바일 5개 + 더보기 배치.
- `index.html`: 하드코딩 메뉴 제거, 설정 하위 메뉴와 인증/새로고침 연결. `showPage`와 보기 상태는 유지한다.

## 저장 및 배포

`tok_settings.navigation_config`에 `{ "version": 1, "order": ["home", ...], "hidden": [] }`를 저장한다. 저장에는 `user_id`와 `navigation_config`만 전송해 심볼, 시간 설정, 색상 설정을 보존한다. 기존 소유자 기반 RLS를 변경하지 않는다. 미지원 ID, 중복 ID, 설정 숨김은 읽을 때 제거하고 누락된 메뉴는 기본 순서로 추가한다.

프런트엔드 배포 전에 `supabase/migrations/20261004234349_tok_navigation_config.sql`을 적용한다. 기존 행은 갱신하지 않고 nullable JSON 컬럼과 형식 검사만 추가한다. 로그인 변경 시 즉시 기본값으로 초기화하고 이전 계정의 늦은 응답은 무시한다. 변경은 즉시 표시하고 저장 실패 시 확인된 설정으로 복구한다.

드래그 핸들은 마우스·터치를 지원한다. 키보드에서는 핸들에 초점을 두고 위/아래 화살표를 사용한다. Escape로 드래그를 취소한다. 저장 중에는 중복 변경을 막는다.

## 검증

`tests/navigation-settings.cjs`는 외부 요청을 차단하고 사용자별 설정 저장을 모사한다. 기본값, 마우스/터치/키보드 순서 변경, 5번째 경계 이동, 숨김, 현재 페이지 이동, 모두 숨김, 설정 접근, 부분 저장, 새로고침, 계정 전환, 늦은 읽기/쓰기, 실패 복구와 390px 여섯 칸 배치를 확인한다.

기존 홈 레이아웃, 사이드바 접기/아이콘 위치, 일정 패널과 클릭, 공통 보기 전환, 모두의 눈 토글, 할일 그룹 드래그, 앱 심볼 테스트도 확인했다. 실제 사용자 데이터를 수정하지 않고 운영 DB의 컬럼/제약조건/RLS 메타데이터를 확인했다.

Supabase 보안 진단은 적용 전후 동일하다. 이번 변경과 무관한 기존 항목은 Google Calendar 두 테이블의 [RLS 정책 미설정 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)와 [유출 비밀번호 보호 설정](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)이며, 이번 범위에서 변경하지 않았다.
