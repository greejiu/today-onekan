## 구현

- 전체 메뉴: 지금한칸 / 구분선 / 일정·작업·목표 / 구분선 / 시간추적·같이한칸 / 구분선 / 기록·설정. 계정·로그아웃, 180px 너비, 데스크톱 빠른 입력 제거 상태를 유지했다.
- 일정 진입 시 전용 메뉴로 교체한다. 페이지와 사이드바 표시 상태는 별도 변수이며, 뒤로가기는 본문을 렌더하거나 날짜·월·보기·필터·스크롤을 초기화하지 않는다. 전체 메뉴에서는 일정 활성 상태를 유지한다.
- 달력·목록은 기존 `showScheduleMode()`와 기존 DOM을 사용한다. 데스크톱 본문 전환부는 숨기고, 모바일 전환부와 사이드바 버튼은 같은 보기 상태를 반영한다.
- 범주 목록은 기본 → 기존 순서의 사용 중 범주 → 연결 일정이 있는 보관 범주 순서다. 보관됨은 보조 문구만 표시한다. 접기와 눈 토글은 독립이며 긴 이름은 말줄임, 많은 범주는 내부 스크롤로 접근한다. 낮은 창에서는 전용 메뉴도 스크롤하여 계정 영역과 겹치지 않는다.
- 필터는 일정 화면 전용 월·날짜 조회와 여러 날 띠 배치에만 적용한다. 원본 `events`, 집·기록·공유 수집은 변경하지 않는다. 건수, +N개, 날짜 상세, 목록, 빈 상태가 동일한 필터를 사용한다.
- 눈 설정과 접기 상태는 `tok_schedule_categories:<userId>`에 저장한다. 처음과 새 범주는 표시, 삭제된 ID는 무시한다. 계정 바인딩 시 메모리 설정과 열린 범주 편집창을 초기화한다. 범주 데이터 로딩의 이전 계정 응답도 반영하지 않는다.
- 모바일 범주 시트와 데스크톱은 하나의 범주 목록 노드를 공유한다. 760/761px 변경은 노드 위치만 옮기며 일정·범주 입력창은 유지한다. Escape와 포커스 복원, 눈 버튼의 범주명·동작 이름과 aria-pressed, 접기의 aria-expanded를 제공한다.
- 범주 수정은 공통 항목 메뉴와 기존 설정의 저장·검증을 재사용한다. 이름·색 저장을 `saveManagedCategory()`로 함께 처리하고, 기본 색은 기존 `saveDefaultCategoryColor()`를 사용한다. 빈 이름·예약 이름 검증, 실패 시 입력 보존, 성공 시 기존 화면과 설정 갱신을 확인했다. 보관 범주는 기존 정책대로 수정하지 않고 설정에서 다시 사용하도록 안내한다.
- 새 DB 컬럼·마이그레이션·권한 변경 없음. 탐색·필터·보기·뒤로가기·접기는 DB에 쓰지 않는다.

## 실행한 검증

Windows Chrome headless, Asia/Seoul, 모든 네트워크를 가로채는 기존 fixture와 메모리 DB를 사용했다. 운영 데이터에는 접속하거나 쓰지 않았다.

- `tests/schedule-sidebar.cjs`: 메뉴 순서·구분선, 진입·뒤로가기·재진입의 상태 유지, 월/오늘 이동, 달력·목록 활성 동기화, 실제 일정 수정과 목록에서 여러 날 일정 저장, 공통 필터·건수·+N개·여러 날 띠·기본·보관 연결·모두 숨김 문구, 새/삭제 범주 처리, 집·공유 입력의 필터 독립, 범주 수정 예약 이름·성공·실패·기본 색·보관 정책, 눈/우클릭/메뉴 분리, 계정별 복원·새로고침, 접기·키보드·Escape·포커스 복원, 일정/범주 입력의 경계 유지, 중복 DOM ID·새 JavaScript/콘솔 오류 없음, 탐색 DB 쓰기 없음.
- 화면: 1366×768, 1440×900, 1440×320, 390×844, 760×768, 761×768. 긴 범주명·40개 이상 목록, 기본·검정·치즈 테마. 스크린샷을 직접 확인했다.
- `tests/sidebar-navigation.cjs`: 새 구조에 맞춘 기존 메뉴·키보드·입력·날짜·목록 스크롤·다른 페이지 연결·모바일 더보기·계정 영역 회귀 검증 통과.
- `tests/home-layout.cjs`: 집의 기존 레이아웃·날짜·스크롤·입력·드래그·모바일 동작 회귀 검증 통과.
- `tests/app-symbols.cjs`: 기존 아이콘 설정·계정 전환·저장 실패·테마·파비콘 회귀 검증 통과.
- 기존 미추적 `tests/task-management.cjs` 원본은 이미 제거된 `#quickTaskInputSide`를 찾아 중단한다. 원본 파일은 보존했다. 실행 시에만 현재 빠른 입력의 값 설정으로 대체한 호환 검증은 작업 탭·추가창·입력·프로젝트·경계·테마·쓰기 없음 검증을 통과했다.
- 앱 스크립트 문법, 테스트 문법, `git diff --check` 확인.

## 후속 배포 요청 (2026-10-03)

사용자의 배포 요청에 따라 전체 메뉴·일정 사이드바 변경만 담은 별도 배포본을 준비했다. 기존 작업 화면 개선은 배포본에서 제외하고 로컬 파일에 보존했다. 배포본을 대상으로 `tests/schedule-sidebar.cjs`와 `tests/sidebar-navigation.cjs`를 다시 실행해 통과했으며, GitHub Pages가 사용하는 main에 반영한다. 운영 사용자 데이터에 쓰는 검증은 수행하지 않는다.
