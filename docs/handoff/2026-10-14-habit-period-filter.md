# 인계: 습관 진행중/보관/종료 탭 → 실천 기간(시작일·종료일) 필터

- 작성일 / 작성 AI: 2026-10-14 / Claude Code
- 브랜치: `codex/habit-period-filter` (기준 `origin/main` 67e5716)

## 목적 (결 요청)
시작일·종료일로 실천 기간을 관리하므로, 겹치는 '진행중 / 보관 / 종료' 탭과 수동 상태 관리를 없앤다. 보관은 목록에서 숨기는 용도로 유지한다.

## 작업 전 확인한 것
- 상태 저장 방식: 습관에 진행중/종료 상태 열이나 종료 시각 열이 없다(`supabase/migrations` 확인).
  - '종료' = `end_date`가 오늘보다 앞이면 화면에서 계산한 값이었다.
  - '보관' = `is_active=false`. 보관·재개 이력은 `tok_habit_pauses`(paused_at, resumed_at)에 있다.
- 추가·수정 창에는 '진행중/종료'를 직접 고르는 칸이 없었다.
  - 수동 상태 변경은 목록의 '재개하기' 하나뿐이었다. 기간이 끝난 습관에서 누르면 `end_date`를 지웠다.
- 오늘 할 일(`habitItemsForDate`, `habitPeriodOccurrences`, `isHabitDueOnDate`)은 이미 요구와 같았다.
  - 시작일·종료일 당일 포함, 빈 값은 제한 없음, 반복 요일·주기 적용, 보관이면 숨김.
- 시작일·종료일을 저장하는 곳은 추가·수정 창 두 곳뿐이고, 둘 다 종료일 < 시작일이면 이미 저장을 막는다.
  - 끌어 옮기기는 회차 날짜(`occurrence_*`)만 바꾼다.

## 바꾼 것
- `index.html`
  - 탭 `#habitsTabRow` 삭제 → 필터 `#habitPeriodFilter`(현재 / 시작 예정 / 기간 종료 / 보관 / 전체, 기본 '현재').
  - `habitLifecycleState(h, 날짜)`: 저장 값 없이 계산한다. 보관(`!is_active`) → `archived`, 시작일이 미래 → `upcoming`, 종료일이 지남 → `ended`, 나머지 → `current`.
    - 예전에는 시작 전 습관도 '진행중'에 섞여 있었다.
  - `habitFilterMatches`, `HABIT_FILTER_LABEL`, `habitEmptyText`를 추가했다.
  - '재개하기' → '복원하기'. `is_active`만 켠다. 종료일을 지우던 코드는 삭제했다.
    - 버튼은 탭이 아니라 보관 여부로 정한다(보관이면 복원, 아니면 보관).
  - 줄 표시: 시작 예정은 'MM/DD 시작', 기간 종료는 'MM/DD 종료'. 밀린 일수 배지는 '현재'만.
  - 목표(프로젝트) 화면의 습관 상태 글자를 새 이름으로 바꿨다.
  - 홈 습관 배너는 '현재'만 센다(시작 전 습관은 원래 예정일이 없어 결과는 같음).
- `assets/habit-views.js`
  - 필터로 목록·보드·달력 회차를 거른다.
  - 목록 줄 보조 정보: 시작 예정 '시작일 YYYY-MM-DD', 기간 종료 '종료일 YYYY-MM-DD', 그 밖은 기존 '다음 예정일'.
- `assets/item-views.js`: 저장되는 보기 설정 `lifecycle` 허용값을 새 값으로 바꿨다.
  - 예전에 저장된 'active'는 기본값 '현재'로, 'archived'·'ended'는 그대로 쓴다.
- `assets/schedule-views.css`: 필터 선택칸 모양.

## 기존 데이터 처리 (실제 적용)
- DB 변경·데이터 수정 없음. 상태 열이 원래 없어서 지울 필드도 없다.
- 보관 습관: `is_active=false` 그대로 → '보관'에 나온다.
- 예전 '종료' 습관: 정의상 모두 `end_date`가 있다 → '기간 종료'에 나온다.
  - 종료일 없는 '종료' 습관은 생길 수 없었다. 임의 날짜를 넣은 습관도 없다.
- 예외(복구 불가, 보고만): 예전 '재개하기'로 종료일이 지워진 습관은 이미 `end_date`가 비어 있어 '현재'로 나온다.
  - 지워진 종료일의 근거(이력 테이블 등)가 없어서 되살리지 않았다.
- 보관·복원 이력(`tok_habit_pauses`)은 계속 남긴다.
  - 복원일은 밀린 일수 계산 기준(앵커)으로 쓰인다(쉰 기간을 밀린 걸로 치지 않는 기존 규칙). 습관의 시작일·종료일은 바꾸지 않는다.
