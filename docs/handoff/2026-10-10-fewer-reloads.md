# 인계: 저장 뒤 다시 불러오기 줄이기 (검토 4번)

- 작성일 / 작성 AI: 2026-10-10 / Claude Code
- 브랜치: `codex/fewer-reloads` (기준 `origin/main` 4df75ab)

## 문제
- 이름 수정, 빈칸 추가(연속 입력), 끌어 옮기기처럼 테이블 하나만 바꾸는 저장도 매번 `loadAll()`로 13개 테이블을 전부 다시 불러왔다.
- 불러오기가 겹치면 요청이 동시에 여러 벌 나갔다(연속 입력, 포커스와 화면 복귀가 같이 오는 경우). 늦게 온 옛 응답이 새 응답을 덮을 수도 있었다.

## 한 일 (`index.html`)
- `requestSync`: 불러오기 줄을 하나로 만들었다. 이미 도는 것이 있으면 그것이 끝난 뒤 한 번만 더 돈다(겹친 요청은 합침, 전체가 하나라도 끼면 전체로).
  - `loadAll()`은 이 줄을 거친다. 실제 본문은 `loadAllNow()`다.
- `reloadTables([...])`: 할일·일정·습관·담아두기 중 바뀐 테이블만 다시 불러온다.
  - 실패하거나 아직 이 사용자 데이터가 없으면 전체 불러오기로 넘어간다.
- 화면 다시 그리기는 `renderAfterLoad()`로 분리했다. `loadAll`과 같은 순서다(보기 묶기 → 지난 반복 일정 이동 → 전체 렌더).
- 바꾼 호출부(한 테이블만 바뀌는 곳):
  - 하루종일·시간블럭·타임라인·다가오는·지금 한칸 블럭의 빈칸 추가
  - 다가오는 등 날짜 칸 추가(`wireDateAddSlot`)
  - 담아두기 추가, 맨 위 빠른 추가(`quickAddTodoToday`)
  - 범위 추가(`commit@6644` 근처)
  - 이름 수정 2곳과 습관 이름 수정
  - `moveItemToZone`(담아두기↔할일은 두 테이블)
- 반복·삭제·범주·시트 저장처럼 여러 테이블에 영향이 갈 수 있는 곳은 그대로 `loadAll()`이다.
- `autoRefreshIfStale`: 포커스와 화면 복귀가 같이 와도 한 번만 불러오도록, 시각 표시를 바로 한다.
- DB 변경 없음. 공개 범위 변경 없음.
