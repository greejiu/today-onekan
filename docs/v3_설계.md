# 오늘한칸 v3 설계 (프로젝트 중심 불렛저널)

상태: **1단계 체험판 구현 (2026-11-15)**. 주소 `https://greejiu.github.io/today-onekan/v3/`. 저장은 이 기기 브라우저(localStorage)만. DB(`bj_`)는 아직 만들지 않았다.
시작: 2026-11-15. 결정이 바뀌면 이 문서를 먼저 고친다.

## 1. 한 줄 정의

할일 앱이 아니라 **프로젝트 중심의 불렛저널 계획 앱**이다.
**무엇을 할지**(구조)와 **언제·어떻게 할지**(계획)를 따로 관리하고, 구조에서 작업을 꺼내 계획에 놓는다.

```
[구조: 무엇을]   영역 → 프로젝트 → 작업
                              │ 계획에 놓기
                              ▼
[계획: 언제]     연간 → 월간 → 주간 → 일간 → 타임라인(지금)
```

- 예: 독서(영역) → 『책 이름』(프로젝트) → 1장 읽기(작업)
  → 11월(월간) → 셋째 주(주간) → 11/15(일간) → 14:00~15:00(타임라인)

## 2. 확정한 것

| 항목 | 결정 |
|---|---|
| 코드 | 새로 쓴다. 기존 `tok_` 앱 코드는 고치지 않는다 |
| 저장소 | 이 저장소 안 `v3/` 폴더 (예정). 지금 앱은 그대로 둔다 |
| DB | 같은 Supabase 프로젝트, 새 접두사 `bj_` 테이블. 기존 `tok_` 테이블은 건드리지 않는다 |
| 기존 기록 | 처음엔 가져오지 않는다. 새 앱이 익숙해지면 한 번에 옮길지 정한다 |
| 첫 화면 | **오늘** |
| 구조 | **영역 → 프로젝트 → 작업**. 프로젝트와 계획은 별개다 |
| 계획 | 작업을 **연간·월간·주간·일간**에 놓아 언제 할지 정한다 |
| 프로젝트 없는 작업 | 허용한다. **"기본"**으로 모아 보여 준다 (2026-11-16 "미분류" → "기본") |
| 영역에 바로 붙는 작업 | 허용한다 (프로젝트 없이 영역만) |
| 타임라인 | **지금한칸 타임라인을 그대로 가져온다** (동작 방식 포함, 5장) |
| 완료 체크 | **둘 다.** 계획마다 "그날 몫 했다" 체크 + 작업 자체 완료 체크 |
| 시간블럭 | 첫 버전에는 **넣지 않는다.** 타임라인과 역할이 겹치고, 첫 버전을 작게 하기 위해. 써 보고 필요하면 추가 |
| 일정 | **작업으로 다룬다.** "14:00 약국 가기", "세수하기" 같은 작은 단계도 모두 작업 |
| 반복 | 첫 버전에는 **반복 기능을 넣지 않는다.** 대신 **"어제 계획 가져오기"** 버튼 (7장). 써 보고 불편하면 반복 추가 |
| 생활 작업 | **"생활" 영역**을 만들어 약국 가기, 세수하기 같은 작업을 둔다 |
| 옮기기 | 오늘·지난 계획을 뒤로 미루면 ">" 흔적을 남긴다. 옮겨 간 계획을 원래 날로 보내거나 ">" 줄에서 "다시 오늘로 되돌리기"를 하면 흔적 없이 되돌린다(옮겨 간 곳을 이미 체크했으면 막고 안내). 아직 안 온 날끼리·앞당기기는 날짜만 바꾼다. "날짜 고르기…"로 아무 날에나 |
| 주 시작 | **일요일** (결의 주간 노트 기준) |
| 주간 화면 | 결의 노트 방식: 왼쪽 = 이번 주 목록을 **영역별로 고정**(영역 칸에 바로 적기), 오른쪽 = **7일**. 왼쪽 줄을 날짜 칸으로 끌어 놓으면 같은 작업에 그날 계획. 날짜를 누르면 그날 오늘 화면 |
| 월간 화면 | 결의 노트 방식: 하루 **3줄 = 오전·오후·저녁**(오전 12시 전 / 오후 12~18시 / 저녁 18시 이후). 빈 줄(·) = 빈 시간. 시간 있는 계획은 **걸친 구간을 모두** 채움(9~18시 출근 = 오전·오후). 시간 없는 계획은 구간을 고름(⋯ 메뉴·자세히에서 적기·끌기). 구간 없는 계획은 칸에 +N. 칸을 누르면 그날 3구간 자세히. 휴대폰은 글자 대신 색 막대. 시간을 빼도 구간은 남음 |
| 영역 표시 | 목록·타임라인에는 영역 이름(·기본)을 글자로 쓰지 않고 **영역 색**으로만 보여 준다. 날짜 아래 색 범례, 프로젝트 이름은 글자로 표시. 지금 카드에만 영역 칩 |
| 기존 기능(습관·타이머·같이한칸 등) | **보류**. 첫 버전에는 넣지 않는다 |

처음 쓸 영역: **일, 그림공부, 독서, 브랜딩, 여가, 생활** (2026-11-15 결의 노트 기준. 설정에서 이름·색·순서·숨기기·추가)

## 3. 원칙

1. **모든 계획 단계는 선택이다.** 오늘에 바로 적어도 된다. 위 단계는 필요할 때 꺼내 쓰는 창고다.
2. **끌어오기 방식.** 오늘 화면 옆 "이번 주에서 가져오기" 패널에서 작업을 끌어와 놓으면 그게 계획이 된다.
3. **지금은 1개.** 타임라인에서 지금 시각에 놓인 작업을 화면 맨 위에 크게 보여 준다 (기존 지금한칸 IA-02와 같은 생각).
4. **완료가 위로 올라간다.** 작업을 끝내면 프로젝트 진행률과 월간·주간 계획에 바로 반영된다 (짧은 보상).
5. **첫 버전은 작게.** 기존 앱처럼 기능을 한꺼번에 늘리지 않는다.

## 4. 개념

| 개념 | 뜻 | 예 |
|---|---|---|
| 영역 | 끝이 없는 관심 분야 | 독서, 그림, 취업(일), 생활 |
| 프로젝트 | 끝이 있는 일. 영역에 속한다 (영역 없음도 허용) | 『책 이름』 완독, 포트폴리오 완성 |
| 작업 | 프로젝트를 이루는 한 줄. 프로젝트·영역 없이도 있을 수 있다 | 1장 읽기, 표지 스케치 |
| 계획 | 작업을 어느 기간에 놓았는지. 한 작업이 여러 단계에 동시에 놓일 수 있다 | 1장 읽기 → 11월, 셋째 주, 11/15 14:00 |
| 지금 | 타임라인에서 지금 시각에 놓인 작업 | ▶ 1장 읽기 |

불렛 기호 — **설정(⚙)에서 직접 정한다** (2026-11-15 결 지정 기본값)

```
•  할일        •  완료 (줄긋기)
*  일정        >  다음으로
-  메모
```

- 한 칸에 3글자까지. 완료를 비우면 할일·일정의 원래 기호를 그대로 쓴다.
- "완료하면 줄긋기"를 켜고 끌 수 있다(기본 켬). 오늘 몫 완료와 작업 완료 모두 줄을 긋는다.
- 참고: Ryder Carroll의 불렛저널 방식(× 완료, < 미래로 보냄)을 바탕으로 했다.

## 5. 타임라인 (지금한칸에서 그대로 가져옴)

2026-11-15 기준 `index.html`의 `renderAgendaTimeline`·`attachAgendaTimelineItemDrag`·`attachAgendaTimelineAddDrag`, `assets/agenda-markup.js`, `assets/schedule-drag.js`에서 확인한 동작이다. 결정 근거는 `docs/DESIGN_DECISIONS.md` DRAG-05~11, BLOCK-03.

| 항목 | 동작 |
|---|---|
| 하루 범위 | 설정의 하루 시작~끝 (기본 06:00~24:00) |
| 눈금 | 15분 한 칸, 1시간 = 36px. 정시 선은 진하게, 30분 선은 연하게. 시간 라벨 12px |
| 항목 높이 | 최소 24px (이름 14px이 들어가게) |
| 지금 선 | 오늘 열에만 빨간 가로선. 1분마다 위치만 갱신 |
| 겹침 | 겹치는 항목끼리 열을 나눔. 같은 겹침 묶음 안에서는 폭을 통일 |
| 자정 넘김 | 23:00~01:00은 날짜별로 나눠 보여 줌. 00:00에 끝나면 다음 날엔 안 보임 |
| 빈 곳에 추가 (마우스) | 누르면 30분 한 칸 추가, 끌면 범위(30분 단위) |
| 빈 곳에 추가 (터치) | 짧게 탭 = 그 칸에 추가 / 움직이면 스크롤 / 0.3초 누르면 진동 후 범위 선택, 끌지 않고 떼면 종류 메뉴 |
| 항목 짧게 탭 | 이름 수정 |
| 항목 이동 | 0.3초 누른 뒤 끌기. 30분 단위, 소요 시간 유지. 다른 날 열로도 이동 |
| 길이 조절 | 항목 위·아래 끝 8px을 끌기. 15분 단위. 짧은 항목은 0.3초 누르면 이동이 우선 |
| 미리보기 | 원래 자리는 흐리게, 놓을 시각에 반투명 칸 |
| 저장 | 한 번에 저장, 저장 중 잠금, 10초 동안 실행 취소 |
| 앞 표시 | 할일 체크박스, 일정 점 (v3에서는 작업 체크박스로) |

v3에서 달라지는 점: 타임라인에 놓이는 것은 **작업의 계획**이다. 옮기거나 길이를 바꾸면 계획의 시간만 바뀌고, 작업 자체(이름·프로젝트)는 그대로다.

## 6. 데이터 구조 초안 (아직 만들지 않음)

- `bj_areas`: 영역. 이름, 색, 순서, 보관 여부
- `bj_projects`: 프로젝트. 영역(선택), 이름, 상태(진행·완료·보류), 색은 영역에서 물려받기 가능
- `bj_tasks`: 작업. 영역(선택), 프로젝트(선택), 이름, 종류(할일·일정·메모), 상태(열림·완료·취소), 순서
- `bj_plans`: 계획 (작업을 기간에 놓은 기록). 한 작업에 여러 개 가능
  - 단계: 연간 / 월간 / 주간 / 일간
  - 기간 시작일: 2027-01-01(연), 2027-03-01(월), 그 주 월요일(주), 날짜(일)
  - 일간만: 시작 시각, 소요 시간 (없으면 시간 없는 오늘 목록, 있으면 타임라인)
  - 상태: 열림 / 완료 / 옮김
- `bj_settings`: 하루 시작~끝 시각 등
- 계획에 바로 적으면 "기본" 작업이 자동으로 함께 생긴다 (계획은 항상 작업을 가리킨다)
- 완료는 두 곳: `bj_plans.상태`(그날 몫) / `bj_tasks.상태`(작업 끝). 계획을 체크해도 작업은 자동 완료되지 않는다. 한 번만 놓인 작업이면 작업 완료도 함께 할지 묻는다 (구현 때 정한다)
- 일정은 따로 테이블을 두지 않는다. 시간이 정해진 작업 = 타임라인에 놓인 계획

## 7. 오늘 화면 스케치

```
┌──────────────────────────────────┐
│ ▶ 지금: 1장 읽기  (독서 · 『책 이름』) │
├────────────────────┬─────────────┤
│ 11/15 (일) 오늘      │ 이번 주에서   │
│ 시간 없음            │ • 자소서 초안 │
│ • 이력서 1줄 고치기   │ • 표지 디자인 │
│ ─ 타임라인 ─         │ ↑ 끌어오기   │
│ 14:00 ▓ 1장 읽기     │             │
│ 15:00               │             │
└────────────────────┴─────────────┘
  [어제 계획 가져오기]
```

**어제 계획 가져오기** (반복 대신)
- 어제 일간 계획 목록을 보여 주고, 오늘로 가져올 것을 고른다. 시간도 그대로 가져온다.
- 완료한 것도 고를 수 있다 (세수하기처럼 매일 하는 작업).
- 가져오면 **같은 작업에 오늘 계획이 하나 더 생긴다** (작업을 새로 만들지 않음). 어제 체크는 그대로 남는다.
- 안 끝난 계획을 넘기는 **옮기기(>)**와는 다르다. 옮기기는 어제 계획을 "옮김"으로 바꾸고 오늘에 놓는다.

## 9. 아직 정할 것

1차 설계에서 정할 것은 끝났다. 아래는 보류 또는 구현하면서 정한다.

- 기존 기능 중 v3에 가져갈 것 (보류)
- 계획을 체크할 때, 한 번만 놓인 작업이면 작업 완료도 함께 할지 묻는 방식 (구현 때)
- "지금"을 고르는 규칙: 지금 시각에 놓인 계획이 여러 개거나 없을 때 (구현 때)
- 화면 디자인(색, 글꼴, 모바일 배치)
