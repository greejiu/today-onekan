# 오늘한칸 v3 설계 (프로젝트 중심 불렛저널)

상태: **설계 중**. 아직 코드와 DB는 만들지 않았다.
시작: 2026-11-15. 결정이 바뀌면 이 문서를 먼저 고친다.

## 1. 한 줄 정의

할일 앱이 아니라 **프로젝트 중심의 불렛저널 계획 앱**이다.
큰 목표를 위에서 아래로 쪼개서 내려보내고, 마지막에 "지금 할 1개"로 이어지게 한다.

```
영역 → 프로젝트 → 연간 → 월간 → 주간 → 일일 → 지금
```

## 2. 확정한 것

| 항목 | 결정 |
|---|---|
| 코드 | 새로 쓴다. 기존 `tok_` 앱 코드는 고치지 않는다 |
| 저장소 | 이 저장소 안 `v3/` 폴더 (예정). 지금 앱은 그대로 둔다 |
| DB | 같은 Supabase 프로젝트, 새 접두사 `bj_` 테이블. 기존 `tok_` 테이블은 건드리지 않는다 |
| 기존 기록 | 처음엔 가져오지 않는다. 새 앱이 익숙해지면 한 번에 옮길지 정한다 |
| 첫 화면 | **오늘** |
| 프로젝트 없는 불렛 | 허용한다. "미분류"로 모아 보여 준다 |
| 영역 | 프로젝트 위에 **영역**을 둔다. 예: 독서(영역) → 책 이름(프로젝트) |
| 기존 기능(습관·타이머·같이한칸 등) | **보류**. 첫 버전에는 넣지 않는다 |

## 3. 원칙

1. **모든 단계는 선택이다.** 오늘 화면에 바로 적어도 된다. 위 단계는 필요할 때 꺼내 쓰는 창고다.
2. **끌어오기 방식.** 오늘 화면 옆 "이번 주에서 가져오기" 패널에서 하나를 끌어오면 그게 계획이 된다.
3. **지금은 1개만.** 화면 맨 위에 크게 보여 준다.
4. **완료가 위로 올라간다.** 일일 불렛을 끝내면 주간·월간·프로젝트 진행률이 바로 오른다 (짧은 보상).
5. **첫 버전은 작게.** 기존 앱처럼 기능을 한꺼번에 늘리지 않는다.

## 4. 개념

| 개념 | 뜻 | 예 |
|---|---|---|
| 영역 | 끝이 없는 관심 분야 | 독서, 취업, 그림, 건강, 치즈 |
| 프로젝트 | 끝이 있는 일. 영역에 속한다 (영역 없음도 허용) | 『책 이름』 완독, 포트폴리오 완성 |
| 불렛 | 한 줄짜리 기록. 할일·일정·메모 | • 1장 읽기 |
| 단계 | 불렛이 놓인 기간의 크기 | 연간 / 월간 / 주간 / 일일 |
| 지금 | 지금 손에 든 불렛 1개 | ▶ 1장 읽기 |

불렛 기호 (참고: Ryder Carroll의 불렛저널 방식, 앱에 맞게 바꿀 수 있음)

```
•  할일        ×  완료
○  일정        >  다음으로 옮김
–  메모        <  미래로 보냄
```

## 5. 데이터 구조 초안 (아직 만들지 않음)

- `bj_areas`: 영역. 이름, 색, 순서, 보관 여부
- `bj_projects`: 프로젝트. 영역(선택), 이름, 상태(진행·완료·보류), 색은 영역에서 물려받기 가능
- `bj_bullets`: 불렛 하나로 모든 단계를 표현
  - 종류: 할일 / 일정 / 메모
  - 상태: 열림 / 완료 / 옮김 / 취소
  - 단계: 연간 / 월간 / 주간 / 일일
  - 기간 시작일: 2027-01-01(연), 2027-03-01(월), 그 주 월요일(주), 날짜(일)
  - 부모 불렛: 어느 위 단계 불렛에서 쪼개져 내려왔는지
  - 프로젝트(선택), 영역(선택)
- 지금: 불렛 1개를 가리키는 값 (구현 때 정한다)

## 7. 만드는 순서 (제안)

1. 오늘 + 지금
2. 영역 · 프로젝트
3. 주간
4. 월간
5. 연간

데이터 구조는 처음부터 모든 단계를 담을 수 있게 짜고, 화면은 하나씩 늘린다.
