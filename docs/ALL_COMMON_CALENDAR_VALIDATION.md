# 모두 통합 보기와 공통 달력

기준 main: `670a14067ffb50021c38e6b04bf5797628ec954a`. 기존 작업 폴더의 미커밋 변경을 보존하고, 이미 연결된 작업 체크아웃에서 `codex/all-common-calendar`를 생성했다. 기존 GitHub Pages 배포 방식을 사용한다.

## 표시 모델과 저장

| 종류 | 원본과 기간 | 분류·조작 |
|---|---|---|
| 일정 | `tok_events.id`, `event_date`, `end_date`, `event_time`, `end_time`, `all_day`, 실제 소요시간 | `category_id`는 일정 그룹, `shared_category_id`는 공용 범주. 기존 상세·메뉴·기간 수정 사용. 완료 체크 없음 |
| 할일 | `tok_todos.id`, `start_date`, `occurrence_end_date`, `todo_time`, `end_time`, `all_day`, 실제 소요시간 | `group_id`, `tag_id`, `project_id` 유지. 기존 완료·취소·반복 다음 회차 생성 사용 |
| 습관 | 원본 `tok_habits.id`와 `habit-views`의 조회 범위 회차·완료·건너뜀 표시 행 | 원본 관리 카드로 대체하지 않음. 기준 회차 날짜와 실제 기록 날짜를 구분. 기존 완료·건너뜀·취소와 제한 재사용 |

통합 표시 행은 `kind`, `source_id`, `display_id`, `period`와 원래 필드를 함께 갖는다. 표시 ID는 종류를 포함하며, 습관은 원본 ID·예정/완료/건너뜀·해당 날짜도 포함한다. 날짜별 구간은 같은 표시 ID와 조작 날짜를 유지한다. 표시 행을 새 테이블에 저장하지 않는다. 그룹 묶음 키도 종류를 포함하고 이름에 출처를 표시한다. 공용 범주는 실제 같은 ID끼리 묶는다.

종일 종료일은 마지막 포함일이고 시간 종료는 배타적이다. 00:00 종료는 다음 날에 겹치지 않는다. 종료 없는 시간 항목의 화면 배치용 구간을 실제 종료로 저장하지 않는다. 드래그 직접 저장은 종료가 있는 일반 일정·할일에만 허용하고, 반복 항목·습관·종료 미정 항목은 기존 수정 경로로 안내한다. 분류·프로젝트·완료 상태를 기간 이동 패치에 포함하지 않는다.

습관 완료 기록은 당시 저장한 시작·소요시간·끝 날짜를 읽고 현재 원본 기간으로 대체하지 않는다. 종료·보관된 원본의 실제 기록도 조회한다. 지연 기록을 예정 날짜에 임의로 연결하지 않는다. 같은 회차의 여러 구간은 한 조작 키로 잠그며 기존 중복 방지·상호 배제 정책을 사용한다. 표시 회차가 조작 불가인 경우 체크와 공통 메뉴 모두 같은 제한을 적용한다. 미래 예정의 수행 가능 여부는 기존 습관 정책을 재사용한다.

날짜 없는 실제 할일은 목록·보드의 포함 옵션과 달력의 목록 진입 안내로 접근한다. `tok_someday`는 통합 대상에서 제외하고 기존 언젠가 이동·관리 경로를 유지한다.

## 보기와 설정

- 모두: 첫 보기는 한달 달력. 달력·목록·보드가 같은 조회 기간 회차/기록을 사용한다. 종류별 눈은 세 보기에 공통 적용되고 모두 숨김도 가능하다. 할일 전체/미완료/완료와 습관 전체/예정/완료/건너뜀 필터를 구분한다.
- 목록은 시작 날짜·시간/이름 정렬, 없음/날짜/종류/그룹/범주/프로젝트 그룹화. 보드는 종류 기본, 그룹/범주/프로젝트 열과 미지정·빈 열을 제공한다.
- `calendar-ui.js`가 네 페이지의 제어부·한달 날짜 칸·선택 날짜 상세 패널을 구성한다. `item-views.js`가 시간축·블럭·겹침·범위 선택·기간 이동을 공유하고 종류별 어댑터가 원본과 저장을 담당한다.
- 일간 보기의 일수는 정수 1~7, 기본 1. 기준 날짜를 유지하며 이전/다음은 일수만큼 이동한다. 한달에서는 일수와 시간 표시 선택을 숨기고 돌아오면 복원한다. 이전 day/four/month 설정은 day+1/day+4/month로 호환하며 잘못된 설정·날짜는 안전한 기본값을 사용한다.
- 사용자·페이지별 `tok_<page>_views:<user>`로 보관한다. 모두의 종류/상태/날짜/보기는 개별 페이지와 지금한칸의 날짜·실행 구성·설정을 변경하지 않는다. 전체 메뉴 복원은 본문을 다시 그리지 않는다.
- 지금한칸의 15분당 9px, 최소 카드 20px, 시간 라벨·30분 구분선·현재 시각선과 블럭 제목/범위 스타일을 기준으로 맞췄다. 기간 조작 스냅은 15분이고 조회만으로 원본을 반올림하지 않는다. 여러 날짜는 공통 시간축과 읽을 수 있는 최소 열 너비로 가로 스크롤한다.
- 범위 추가는 종류 선택 후 해당 추가창에 전달하고 저장 전 확인한다. 취소·Escape·유효하지 않은 드롭·화면/일수/보기/종류/계정 변경 시 드래그를 취소한다. 터치 스크롤은 드래그 저장을 시작하지 않는다.

## 파일과 검증

주요 변경: `assets/all-views.js`, `assets/calendar-ui.js`, `assets/item-views.js`, `assets/schedule-views.css`, 종류별 어댑터와 `index.html`. 관련 브라우저 fixture와 기존 보기 검증을 새 일간 제어부/실제 시간축 좌표에 맞게 갱신했다.

격리 테스트 20개: `all-views`, `calendar-ui`, `habit-views`, `todo-views`, `schedule-views`, `period-model`, `period-ui`, `period-paths`, `period-sql`, `classification-ui`, `classification-sql`, `common-navigation`, `direct-navigation`, `schedule-sidebar`, `sidebar-navigation`, `project-today`, `tag-terminology`, `app-symbols`, `together-ui`, `home-layout`.

새 검증은 통합 ID 충돌, 종류별 그룹/공용 범주, 공유 시간 겹침, 회차/스냅샷/보관·종료·지연 기록, 미지정·날짜 없음·언젠가 제외, 상태 분기, 반복 다음 회차, 여러 위치의 중복 방지, 일반 할일 실제 이동/끝 조절과 native table/ID, 제한 항목·메뉴, 종류 선택 범위 추가, 실패 복원, 계정 분리, 모든 1~7일 범위/이동, 과거 4일 설정, 한달 복원, 드래그 취소, 키보드·모바일·테마를 포함한다. 기존 테스트는 기간·분류·프로젝트·역사·공유·현재 일정·지금한칸 조작을 회귀 검증한다. DB 검증은 별도 PGlite를 사용하고 네트워크는 차단/가로챈다.

화면 근거는 Git에서 제외한 `test-results/all-views/`, `test-results/calendar-ui/`와 기존 종류별 검증 폴더에 저장한다. 1440×900, 1366×768, 390px, 760/761px와 기본·검정·치즈 테마에서 본문 넘침·중복 DOM ID·새 콘솔 오류를 확인한다. 조회·종류 눈·필터·보기 전환은 항목 쓰기를 하지 않는다.

운영 Supabase `mmpsyajgyufdxmmnxqba`의 기존 컬럼과 RLS를 읽기 전용 catalog 조회로 확인했다. 테이블·마이그레이션·RLS·권한 변경은 없으며 운영 데이터 백업/변경이 필요하지 않다. 운영 사용자 항목을 수정하는 실계정 완료·드래그 검증과 실제 모바일 기기 검증은 수행하지 않는다. 쓰기는 격리 fixture/PGlite로 검증한다.

배포는 PR 검토와 현재 정책/필수 체크 확인 후 main 병합 → 기존 Pages build/deploy 성공 → 실제 URL의 HTML/11개 자산과 반영 커밋 비교 순서다. 배포 URL의 로그인 화면은 실제 네트워크로 확인하며 로그인 후 주요 화면은 배포된 HTML과 격리 인증/데이터로 확인한다. 근거 JSON은 `test-results/deployment-verification.json`과 `production-anonymous-smoke.json`에 남긴다. 배포를 되돌릴 때는 이 기능의 앱 커밋을 revert하고 기존 Pages 배포를 사용하면 된다. DB 복구 단계는 없다.
