## 1. 집 화면 3열 (기본 방향 확정)

### 1-1. 구성

| 왼쪽 | 가운데 | 오른쪽 |
|---|---|---|
| 언젠가 | 지금, 한칸 | 다가오는 |
| 날짜를 정하지 않은 할 일 | 선택한 날짜의 할 일·습관·일정 | 이후 날짜별 예정 항목 |
| 기존 정렬·그룹 필터 유지 | 시간블럭 / 타임라인 전환 | 기본 7일, 이전/다음 7일 이동 |

- 기존 '담아두기' 안의 언젠가/다가오는 탭을 각각 독립 카드로 분리한다.
- 가운데에는 시간블럭/타임라인 두 보기만 둔다. 타이머는 후속 단계의 독립 메뉴다.
- 기존 항목 조회·체크·수정·추가·공통 메뉴 기능을 재사용한다.
- 처음 제안한 너비 비율은 **30% / 40% / 30%**. 가운데를 가장 넓게 유지하되 가용 폭에 따라 조정한다.
- 계획 항목을 한 화면에 모두 욱여넣기 위해 글자나 클릭 영역을 축소하지 않는다.

### 1-2. 높이와 스크롤 — 구현 기준안

- 넓은 웹에서는 상단바·본문 여백·현재 표시되는 배너를 제외한 가용 높이에 세 카드를 맞춘다.
- 집 페이지 전체가 내용 때문에 계속 길어지는 대신 각 카드의 목록 내부에서 스크롤한다.
- 카드 제목, 보기 선택, 날짜 이동 등 상단 조작부는 고정하고 목록만 스크롤한다.
- 가운데의 '남아 있는 할일'을 펼쳐도 전체 카드가 화면 아래로 밀리지 않아야 한다. 내용 영역 안에서 보이도록 배치한다.
- 타임라인의 시간 눈금과 항목 높이는 보존한다. 하루 전체를 화면에 맞추기 위해 압축하지 않는다.
- 페이지 전체와 카드 내부에 불필요한 이중 스크롤·가로 스크롤을 만들지 않는다.
- 화면 확대, 낮은 화면 높이, 긴 제목에서도 조작부가 잘리지 않게 한다. 공간 부족 시 자연스러운 세로 스크롤을 허용하는 대체 배치가 고정 높이보다 우선한다.
- 빈 날짜와 시간블럭은 유지하되 과도한 여백을 줄인다. 빈 곳은 '계획이 없어요', PC hover/키보드 focus에서는 테두리와 '눌러서 추가해요'를 보여준다.

### 1-3. 날짜와 보기 — 구현 기준안

- 가운데의 두 보기는 **같은 선택 날짜**를 공유한다.
- 마지막으로 고른 보기와 보기별 스크롤 위치를 기억한다. 새 저장값이 없으면 현행 기본 보기를 유지한다.
- '다가오는'의 범위는 첫 진입 시 내일부터 7일이다.
- 오른쪽 이전/다음 7일 이동은 가운데의 선택 날짜를 바꾸지 않는다.
- 가운데 날짜를 이동해도 오른쪽에서 사용자가 보고 있던 주간 범위가 갑자기 바뀌지 않는다.
- 각 영역은 자체 초기 날짜로 돌아가는 동작을 제공한다. 기존 날짜 라벨 클릭을 재사용할 수 있고 접근 가능한 버튼/명칭을 사용한다.
- 날짜 이동·재렌더의 비동기 응답이 뒤늦게 도착해 이전 날짜 목록으로 덮어쓰지 않도록 확인한다.
- 앞서 제안했던 '다음 7일 펼치기' 대신, 1단계에서는 **현재 존재하는 이전/다음 7일 탐색**을 유지한다.

### 1-4. 언젠가와 모바일

- 언젠가의 기존 정렬, 그룹 필터, 5개 더 보기 규칙을 유지한다.
- PC 자동 추가는 '바닥 도착 → 입력 멈춤 → 다시 아래로 스크롤'일 때만 최대 5개다. 바닥에 닿는 즉시 펼쳐지면 안 된다.
- 모바일은 기존처럼 버튼으로 펼친다.
- 좁은 화면에 3열을 강제하지 않는다.
- **모바일의 새 영역 전환 탭은 아직 상세 확정 전이다.** 1단계는 현행 세로 스크롤 방식과 기능을 유지하는 반응형 대체 배치로 구현한다. 좁은 화면에서 '지금, 한칸'을 우선 볼 수 있는 순서를 구현 기준으로 삼는다.
- 모바일 하단의 타이머 메뉴 신설·설정 이동은 타이머 단계에서 한다.

### 2-1. 1단계와 데이터 변경 작업의 경계

- 1단계는 레이아웃·날짜 탐색·보기 저장·스크롤·DOM 재배치에 따른 연결을 구현한다.
- 드래그의 영역 판별, 표시되는 날짜로의 이동, 내부 목록 가장자리 자동 스크롤은 3열 사용성 범위다.
- **데이터 이동 안전성 수정은 별도 후속 작업으로 추적한다.** 반복 모델/DB/RPC를 광범위하게 바꾸는 작업을 레이아웃 패치에 섞지 않는다.
- 위 표의 기존 문제를 1단계에서 해결했다고 표시하지 않는다. 기존 문제와 새 변경으로 생긴 회귀를 구분해서 결과에 보고한다.
- 후속 데이터 이동 작업은 타이머의 할 일 연결·기록 보존을 구현하기 전에 처리한다.
- 단계 1 완료는 전체 기능의 운영 품질 검증이나 모든 드래그 결함 해결을 뜻하지 않는다.

## 3. 공통 메뉴 (09-27 최신 순서 확정, 후속 구현)

PC 오른쪽 클릭과 PC·모바일 ⋯ 버튼은 같은 메뉴를 연다.

| 대상 | 메뉴 순서 |
|---|---|
| 할 일 | 오늘 하기 → 내일 하기 → **타이머 시작** → 수정 → 그룹 변경 → 복제 → 삭제 |
| 언젠가 | 오늘 하기 → 내일 하기 → 수정 → 그룹 변경 → 복제 → 삭제 |
| 일정 | 오늘 하기 → 내일 하기 → 수정 → 범주 변경 → 복제 → 삭제 |
| 습관 | 이번만 건너뛰기 → 수정 → 그룹 변경 → 복제 → 삭제 |

- 별도 '날짜 변경'/'날짜·시간 변경' 메뉴는 제거하고 상세 수정에서 날짜·시간을 설정한다.
- 타이머 시작은 **할 일에만** 표시한다. 언젠가는 날짜를 정해 할 일로 옮긴 뒤 사용한다.
- 오늘/내일은 사용자의 실제 오늘 기준이며, 보고 있던 달력의 선택 날짜 기준이 아니다.
- 실행 시 날짜를 바로 옮기고 기존 시각·소요시간·여러 날 일정의 기간을 유지한다.
- 이미 해당 날짜라면 해당 동작은 비활성화한다.
- '내일로 옮겼어요 · 되돌리기' 피드백은 구현 기준안이다. 되돌리기도 실패/중복/동시 수정 처리를 고려해야 한다.
- 반복 할 일은 현재 회차만 이동하며 원래 반복 주기·원래 예정일 보존 정책은 유지한다.
- 언젠가 수정창에도 날짜 지정 후 할 일로 이동하는 기능이 필요하다. 현재 메뉴 경로를 없애면서 임의 날짜 지정 기능까지 없애지 않는다.
- 언젠가에도 복제를 제공하려면 현재 모델의 누락을 별도로 구현한다.
- 습관은 선택한 날짜의 회차를 건너뛰며, 건너뛴 상태에서는 '건너뛰기 취소'로 바뀐다. 완료 상태에는 건너뛰기를 표시하지 않는다.
- 건너뛴 습관은 체크박스 대신 × + 건너뜀, × 직접 클릭으로 완료 불가. 항목 전체 클릭은 막지 않는다.
- 삭제는 하단에서 구분한다. **이번 메뉴 라벨 확정만으로 기존 기록까지 지우는 삭제를 승인한 것으로 해석하지 않는다.** 기존 문서 9-B의 기록 보존·종료 원칙과 실제 삭제 동작의 정합성은 후속 메뉴 작업에서 정리한다.
- 기존 문서의 '수행 기록 추가' 등 과거 회차 관리 진입점과 새 간결한 메뉴의 관계는 설계 중이다. 관련 데이터/기록 기능을 레이아웃 단계에서 제거하지 않는다.

## 4. 타이머 (기본안 승인, 후속 구현)

### 4-1. 위치와 연결

- 독립 메뉴: 집 / 일정 / 할일 / 습관 / 타이머.
- 모바일도 다섯 메뉴를 기준으로 설계하고 설정은 상단 톱니바퀴로 진입한다.
- 타이머의 대상은 할 일만이다. 습관·일정·언젠가에는 직접 연결하지 않는다.
- 할 일 공통 메뉴의 '타이머 시작'으로 해당 할 일을 연결한다.
- 시간 설정이 필요한 첫 실행의 상세 흐름, 진행 중 다른 할 일 선택 시 처리, 기본 측정 방식은 설계 중이다.
- 타이머 화면에서 할 일을 고를 수 있다.
- 넓은 화면: 측정 영역 + 오늘 기록 영역. 모바일: 위아래 배치.
- 다른 화면에서도 제목·측정 상태·시간·일시정지·종료가 보이는 작은 진행 표시를 제공한다.

### 4-2. 측정과 종료

- 시간 재기: 0부터 실제 시간을 누적한다.
- 시간 정하기: 목표 시간을 정해 남은 시간을 표시한다.
- 목표 시간의 추천값·직접 입력 UI는 후속 상세 설계 대상이다. 할 일의 기본 입력 단위 30분을 타이머의 필수 단위로 강제하지 않는다.
- 일시정지한 시간은 집중 시간에서 제외한다.
- **종료하면 기록만 저장한다. 할 일은 자동 완료하지 않는다.**
- **'할 일도 완료' 확인창이나 '저장하고 할 일 완료' 버튼을 만들지 않는다.** 완료 체크는 사용자가 기존 목록에서 직접 한다.
- 목표 시간 도달 시 알림·자동 저장·추가 측정 여부와 앱 종료/장시간 이탈 시 최종 정산은 설계 중이다.
- 계획 시각·예정 소요시간과 실제 집중 기록을 분리한다. 미래 날짜의 할 일을 선택했어도 실제 측정 시간은 실제 발생 날짜로 저장한다.
- 자동 휴식 반복/뽀모도로는 이번 기본안에 포함하지 않는다.

### 4-3. 구현 시 충족해야 할 보존 원칙

- 화면 이동과 새로고침 후 상태 복원.
- 동시에 실행되는 타이머는 1개. 탭·기기 간 충돌 정책은 후속 설계.
- 중복 종료/재시도로 기록이 중복 저장되지 않아야 함.
