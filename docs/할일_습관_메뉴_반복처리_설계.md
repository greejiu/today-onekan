  - **할일**: 완료하면 다음 회차 1개를 새 행으로 만듦(기존 방식 유지). ※ 다음 날짜 계산 기준은 "완료일"이 아니라 **그 회차의 예정일(`start_date`)**임(10-6 G 참고 — 과거 문서의 "완료 기준" 표현과 실제 코드가 다름).
  - **습관**: 행을 만들지 않고 시작일(앵커)부터 공식으로 계산. 이번 회차 1개만 활성, 미래 회차는 미리 만들지 않음.
- **프로젝트·포커스는 새로 만든다(확정).** 현재 코드엔 둘 다 없음. DB에는 `tok_focus_sessions`(할일과 `todo_id`로 연결)와 `tok_todo_subtasks` 테이블이 남아 있어 재사용 가능.

## 2. 메뉴 (설계 반영(지피티))
오른쪽 클릭과 ⋯ 버튼은 **같은 메뉴**를 연다(확정).

| 할일 | 습관 |
|---|---|
| 오늘 하기 | 수행 기록 추가 |
| 내일 하기 | 이번 건너뛰기 |
| 집중 시작 | 상세 수정 |
| 상세 수정 | 삭제 (→ 9-B 확정에 따라 기록까지 지우는 삭제는 일반 메뉴에 그대로 둘 수 없음. 이름·동작은 10-6 E 권장안 검토 중) |
| 삭제 | |

- 습관에는 오늘 하기 / 내일 하기 / 집중 시작을 **표시하지 않는다.**
- 건너뛴 습관 회차의 메뉴는 **건너뛰기 취소 / 수행 기록 추가**를 제공(4-A 확정).
- 현재 습관 탭의 "오늘 하기"(바로 완료 처리) 메뉴는 "수행 기록 추가"로 대체.
- 상세 수정은 팝업 하나로 통합(그룹·날짜·시간·반복 등). 프로젝트 칸은 할일일 때만 표시. 현재는 수정 시트가 3개로 흩어져 있음(날짜/시간/반복 시트, 습관 설정 시트, 할일 시트).
- 현재 코드 참고: 우클릭 "날짜 변경" 시트에서 습관의 시작일·반복을 바꾸면 확인 없이 과거 전체가 새 규칙으로 다시 계산됨. "습관 예정일 이동 기능 없음"(10-4) 원칙에 따라 이 경로는 정리 대상.

## 3. 할일: 오늘 하기 / 내일 하기 (확정)
- 뜻: **그 날짜로 이동.**
- 반복 할일은 **이번 회차만 이동**하고 반복 규칙은 유지. 적용 범위는 묻지 않음.
- 반복 할일은 자동으로 건너뛰지 않음. 완료할 때까지 "N일 지남"으로 남음(현재와 같음).
- 필요한 변경: 할일에 **원래 예정일** 칸 추가. 다음 회차는 원래 예정일 기준으로 계산. 늦게 완료한 경우의 다음 날짜는 10-7 6번(확정)을 따름.
  - 현재 문제: 날짜를 옮기면 시작일을 덮어써서 원래 날짜가 사라지고, 다음 회차도 옮긴 날짜 기준으로 계산돼 반복이 밀림(예: "2주마다" 할일을 일요일로 옮기면 이후도 일요일로 밀림. 요일 지정 반복은 영향 없음).

## 4. 습관: 이번 건너뛰기 (설계 반영(지피티))
- 이번 회차에만 적용. 적용 범위 질문 없음.
- 완료로 집계하지 않음.
- 건너뛰기 이력은 보존. (달력 표시는 7-2 권장안 참고)
- 기존 반복 규칙을 유지하면서 다음 예정 회차 1개를 준비.
- 다음 예정일 전에는 그 회차를 오늘 해야 할 습관으로 표시하지 않음.
- 잘못 누른 경우 **건너뛰기 취소** 가능. (화면 표시·메뉴·취소 범위는 4-A 확정)

## 4-A. 건너뛴 습관 표시와 메뉴 (확정, 2026-09-24)
**표시**
- 건너뛴 습관은 체크박스 대신 **×와 "건너뜀" 상태명**을 표시한다.
- **×를 눌러 바로 완료할 수 없게** 한다(×는 상태 표시일 뿐 체크 버튼이 아님).
- 항목 전체의 클릭은 막지 않는다(× 외의 기존 클릭 동작은 그대로).
- **기록 달력에서도 건너뛴 회차에 ×를 표시한다(확정, 09-24).** 수동·자동 건너뛰기 모두 해당. 색상 규칙은 바꾸지 않고 아이콘만 추가(7-1 확정·7-2 권장안의 색 그대로). 건너뛰기를 취소한 회차는 ×를 없애고 미실천 표시로, 수행 기록이 생긴 회차는 완료 표시로 바꾼다.

**메뉴 (⋯ 버튼과 오른쪽 클릭 — 2장의 "같은 메뉴" 규칙)**
1. 건너뛰기 취소
2. 수행 기록 추가

**건너뛰기 취소**
- 해당 회차에만 적용한다. 미래 회차나 반복 주기를 바꾸지 않는다.
- 이미 지난 회차를 취소했다고 해서 **오늘 할 습관으로 다시 올리지 않는다.**

**수행 기록 추가 (건너뛴 회차에서)**
- **클릭한 회차를 대상으로** 삼고, 회차 선택을 다시 묻지 않는다.
- 실제 수행일을 입력받는다.
- 해당 회차가 완료되면 ×를 **완료 표시**로 바꾼다. (건너뛰기 기록은 이력으로 남기고 상태는 완료로 판정 — 9-C·10-2와 같은 방향)

**이번 결정으로 바꾸지 않는 것**
- 색상·달성률 정책(7-1 확정, 7-2·7-3 권장안)은 그대로.

**다른 항목과의 관계**
- 10-2(건너뛴 회차를 "명시적으로 골라" 수행 기록 추가): 건너뛴 회차의 메뉴에서 여는 경우는 **클릭 = 회차 선택**으로 확정. 그 밖의 경우(예정과 다른 날짜로 추가할 때 대상 회차 확인, 10-1·10-6 B)는 여전히 미확정.
- 현재 코드(`f6008e9` 기준): 건너뛰기 기능·기록이 없고 ⋯ 버튼도 없음. 습관 행은 체크박스만 있고, 메뉴는 오른쪽 클릭(`showAgendaItemMenu`)만 있음. → 13장 2단계(습관 기록 구조)에서 함께 구현.

**추가 확정 (2026-09-24, 구현 전 확인 3건에 대한 결의 답)**
1. **실제 수행일은 오늘 또는 과거 날짜만** 입력할 수 있다. 미래 날짜는 선택할 수 없다. (10-1 첫 항목과 같은 내용 → 확정)
2. **지난 회차의 건너뛰기 취소 = 일반 습관 앱처럼 "안 한 상태"로 되돌린다.**
   - 결의 답은 "보통 다른 앱들처럼"이었고, Claude가 아래처럼 구체화했고 **결이 "맞아"로 확인(09-24).**
   - 그 회차는 **미실천(못 한 회차)**이 된다. 달력 표시는 7-1 확정 규칙(연한 빨강)을 그대로 따른다.
   - 오늘 할 습관으로 다시 올리지 않는다(4-A 위 규칙).
   - **자동 건너뛰기(5장)가 그 회차를 다시 "건너뜀"으로 기록하지 않는다.** 다시 기록되면 취소가 무의미해지므로.
   - 취소한 뒤에도 그 회차 메뉴에서 **수행 기록 추가**는 할 수 있다(완료되면 완료 표시).
   - 참고: "다른 앱들처럼"은 습관 앱에서 흔한 방식(건너뛰기를 되돌리면 안 한 날로 돌아감)을 따른 것이고, 특정 앱의 동작을 검증한 것은 아님.
3. **자동 건너뛰기도 취소할 수 있다.** 수동·자동 모두 같은 취소 규칙을 따른다.

**데이터 구현 메모 — 권장안(미확정, Claude)**
- 9-C의 "건너뛰기 취소 = 해당 행 삭제"로는 2번(자동 건너뛰기가 다시 기록하지 않음)을 지킬 수 없음. 앱을 열 때 지난 회차를 정리하는 과정이 행이 없는 회차를 다시 "자동 건너뜀"으로 기록하기 때문.
- 대신 건너뛰기 행을 지우지 않고 **취소 표시(예: `cancelled_at`)**를 남기는 방식을 권장. 취소된 회차는 자동 건너뛰기 대상에서 제외하고, 상태는 미실천으로 판정. 건너뛰기 이력 보존(4장) 원칙과도 맞음.

## 5. 습관: 자동 건너뛰기 (설계 반영(지피티))
- 다음 반복일이 오면 이전 미완료 회차를 자동으로 건너뜀. 이전 회차를 삭제하거나 완료 처리하지 않음.
- 수동 건너뛰기로 다음 회차가 이미 준비돼 있으면 중복 생성하지 않음.
- 습관에만 적용. 반복 할일은 자동으로 건너뛰지 않음.
- 현재 코드: 화면 동작은 이미 이와 같음(새 회차가 오면 최신 회차만 보임). **다만 건너뛴 기록은 저장하지 않고 매번 계산으로 추측함** → 기록 저장이 필요.
- 참고: 매일 습관은 다음 날 바로 자동 건너뜀되므로 "N일 지남"이 생기지 않음(현재도 사실상 동일).

## 6. 습관: 수행 기록 추가 (설계 반영(지피티))
- 예정일을 옮기는 기능이 **아니라** 실제 수행일에 기록하는 기능.
- 토요일 예정 습관을 일요일에 했다면 일요일에 수행 기록을 남김.
- 실제 수행일은 사용자가 고를 수 있음.
- 기존 반복 요일은 바꾸지 않음.
- ~~이미 수행 기록이 있는 날짜에는 중복 기록을 만들지 않음~~ → **10-3 권장안(같은 날 명시적 추가 수행 허용)으로 대체 검토 중.** 현재 DB에는 `habit_id + done_date` 중복 방지 제약이 있어서, 10-3이 승인되면 이 제약을 바꿔야 함.
- 집 화면 습관 체크박스는 10-6 B 권장안 검토 중.
- 날짜 범위·회차 인정 방식은 10-1, 10-6 B 권장안 참고.

## 7. 기록 화면·통계

### 7-1. 확정
- 달력: 못 한 회차(자동 건너뜀 포함) = **연한 빨강** (2026-09-24 결 확정, 옵션 B = 09-13 방식 유지).

### 7-2. 달력 표시 — 권장안(미확정, 지피티)
| 상태 | 표시 |
|---|---|
| 수행 완료 | 완료 색상 + 체크 |
| 예정일이 지난 미실천, 자동 건너뛰기 | 연한 빨강 (7-1 B 규칙) |
| 수동 건너뛰기 | 회색 + 건너뛰기 표시 |
| 원래 예정이 없는 날 | 색 없음 |
| 오늘 진행 중인 회차, 미래 예정 회차 | 미실천으로 표시하지 않음 |

- 색만으로 상태를 구분하지 않고, 아이콘이나 상세 상태명을 함께 제공.
  - **확정(4-A, 09-24):** 건너뛴 회차(수동·자동)의 아이콘은 **×**. 색은 이 표의 규칙을 그대로 따름.
- 이전 지피티 안의 "모든 건너뛰기를 빈칸으로 표시"는 이 권장안으로 대체 검토 중(12장).
- 현재 코드와의 차이(참고): 지금 달력은 **오늘이 예정일이면 아직 안 했어도 빨강**으로 표시함(지난 예정일 판정에 오늘 포함). 아이콘/상태명 없이 색과 ✓만 씀.

### 7-3. 달성률 — 권장안(미확정, 지피티)
- 계산 대상: **결과가 확정된 예정 회차.**

| 회차 상태 | 분자 | 분모 |
|---|---|---|
| 완료 | 포함 | 포함 |
| 수동 건너뛰기 | — | 포함 |
| 자동 건너뛰기 | — | 포함 |
| 기한이 지난 미실천 | — | 포함 |
| 아직 미완료인 오늘 회차, 미래 회차 | 제외 | 제외 |

- 분모가 0이면 0% 대신 **"집계할 기록 없음"**으로 표시.
- 달성률과 함께 **완료 / 수동 건너뛰기 / 미실천 횟수**를 구분해서 표시.
- 추가 수행(10-3)은 실제 수행 횟수에만 반영하고 달성률 분자·분모는 늘리지 않음.
- 현재 코드와의 차이(참고): 지금은 오늘 회차를 미완료여도 분모에 넣고, 분모 0이면 "-"로 표시하며, 건너뛰기 구분 없이 "완료 N/전체 M"만 보여줌.

### 7-4. 현재 확인된 통계 버그 (사실 기록)
- 현재 코드는 "예정일 **이후** 수행 기록이 하나라도 있으면 그 회차는 완료"로 판정해서 기간 끝이 없음.
- 예: 매일 습관을 9/1~9/9 안 하고 9/10에 한 번 하면 통계는 10/10(100%), 달력은 9/1~9/9가 빨강 → 서로 불일치.
- 10-1 권장안(수행 기록이 어느 회차 달성인지 직접 저장)이 승인되면 구조적으로 해결됨(날짜 비교로 추측하지 않게 되므로).
- ⚠️ 정정: 이 문서 첫 버전에서 "완료 인정 범위 = 예정일 ~ 다음 예정일 전날"을 확정으로 적었는데, Claude가 제안한 기준이었을 뿐 승인된 내용이 아니었음 → 폐기(12장).

## 8. 프로젝트 ↔ 그룹 (확정)
- 프로젝트에 그룹을 정하면 → 소속 할일은 그 그룹을 따라감.
- 프로젝트의 그룹을 바꾸면 완료한 것을 포함해 소속 할일 전체가 따라 바뀜(그룹은 분류이지 수행 기록이 아니라서).
- 그룹별 보기에서 프로젝트 할일을 다른 그룹으로 드래그하면 → "프로젝트에서 빼고 이 그룹으로 옮길까요?" 확인 → 예를 누르면 프로젝트에서 빠지고 그룹 변경.
- 프로젝트별 보기(할일만)에서는 드래그로 프로젝트 변경. 상세 수정 팝업에서도 변경 가능.

## 9. 확정된 습관 규칙 + 데이터 설계

### 9-A. 습관 시간 수정 (확정, 2026-09-24)
- **"이번 및 이후"만 제공**한다. **"이번만" 시간 변경은 제공하지 않는다.**
- 과거 완료·건너뛰기 회차의 정보는 변경하지 않는다.
- 현재 구조 참고: 수행 기록(`tok_habit_logs`)은 체크 순간의 시간·길이(`start_minute`, `duration_minutes`)를 따로 저장하고 있어서, 습관 시간을 바꿔도 과거 완료 기록의 시간은 그대로 남음. 회차별 시간 예외 저장 구조는 만들지 않음.

### 9-B. 습관 종료 (확정, 2026-09-24)
- 앞으로의 반복 생성을 중단한다.
- 기존 수행 기록과 과거 회차는 보존한다.
- **기존의 기록까지 함께 지우는 삭제 기능을 그대로 사용하면 안 된다.**
- 현재 구조 참고:
  - 현재 습관 "삭제"는 DB에서 습관 행을 지우고, 수행 기록(`tok_habit_logs`)과 보관 이력(`tok_habit_pauses`)도 **함께 삭제됨**(DB `ON DELETE CASCADE` 확인). 확인 문구도 "기록도 함께 삭제돼요". → 이 동작은 일반 메뉴에 그대로 둘 수 없음.
  - 이미 있는 "종료" 상태(`end_date`가 지나면 종료, 습관 탭 "종료" 목록)는 기록을 지우지 않고, 통계도 종료일까지만 셈 → 확정 내용과 방향이 같음.

### 9-C. 데이터 설계 권장안 (미확정, Claude — 구현 착수 시 확정)
- **이력 보존 수준: (가) 가벼운 방식으로 확정.** 수행·건너뛰기 기록에 원래 예정일을 남김. 반복 규칙 변경 이력 전체 저장은 하지 않음.
- **수행 기록(`tok_habit_logs`) 확장** — 10-1·10-3 권장안이 승인될 경우:
  - `scheduled_date`(date, 비어 있을 수 있음): 이 기록이 달성으로 인정되는 예정 회차. 비어 있으면 "예정 외 추가 수행" 또는 이관된 기존 기록(10-6 F).
  - `kind`: `normal`(회차 달성) / `extra`(추가 수행).
  - 중복 방지 제약 교체: 지금의 `habit_id + done_date` 대신 `habit_id + scheduled_date`(`kind=normal`인 행만). → 한 회차는 달성 기록 1개만 가짐. 한 기록은 `scheduled_date`가 하나뿐이라 두 회차에 중복 집계될 수 없음.
  - 같은 날 추가 수행은 `extra`로만 생김. 중복 클릭은 `normal` 제약에 막히므로 의도적 추가 수행과 구분됨.
- **건너뛰기 기록**: 별도 테이블 권장. 예) `tok_habit_skips(habit_id, scheduled_date, kind: manual|auto, created_at)`, `habit_id + scheduled_date` 중복 방지. ~~건너뛰기 취소 = 해당 행 삭제.~~ → 4-A 추가 확정 2번 때문에 행을 지우지 않고 취소 표시(`cancelled_at` 등)를 남기는 방식으로 변경 권장(4-A 데이터 구현 메모).
  - 건너뛴 회차에 나중에 달성 기록이 생기면(10-2): 건너뛰기 행은 **그대로 두고**(이력 보존), 회차 상태는 "완료"로 판정(달성 기록이 우선).
- **자동 건너뛰기 기록 시점**: 앱을 열 때 지난 회차를 정리하며 기록(반복 일정의 "지난 일정 자동 넘기기"와 같은 방식). **반복 규칙을 바꾸기 전에도 먼저 정리해 둬야** 과거가 새 규칙으로 다시 계산되지 않음.
- 할일: `tok_todos`에 원래 예정일 칸(가칭 `original_date`) 추가.
- 프로젝트: 예) `tok_projects(id, user_id, name, group_id nullable, sort_order, …)` + `tok_todos.project_id`.
- 주의: 현재 체크 해제는 "그 날짜의 기록 전부 삭제"로 동작함. 같은 날 기록이 여러 개가 되면 기록 하나씩 지우는 방식으로 바꿔야 함.

## 10. 반복 처리 권장안

### 10-1. 수행 기록 날짜 및 회차 인정 — 권장안(미확정, 지피티 2차)
- 실제 수행일은 **오늘 또는 과거 날짜만** 허용. 미래 날짜를 실제 수행 완료로 기록할 수 없음. **→ 이 항목은 확정(2026-09-24, 4-A 추가 확정 1번).** 나머지 10-1 항목은 여전히 권장안.
- **실제 수행일**과 **달성 대상으로 인정하는 예정 회차**를 구분.
- 예정일의 일반 체크는 해당 회차를 바로 완료.
- "수행 기록 추가"에서 예정과 다른 날짜를 입력하면 "어느 회차의 수행인지"를 확인. 선택지: 관련 예정 회차 또는 "예정 외 추가 수행". 회차를 자동으로 추측해 확정하지 않음. (→ 10-6 B에서 "대상 회차가 명확하지 않을 때만 확인"으로 완화 제안됨)
- 예: 토요일 회차를 금요일에 미리 하거나 일요일에 늦게 해도, 사용자가 토요일 회차를 고르면 그 회차를 완료로 인정.
- 달력의 실제 수행 표시는 금요일/일요일에 남김. 원래 예정일(토요일)에서 실제 수행일을 확인할 수 있어야 함.
- 같은 수행 기록을 두 회차의 달성으로 중복 집계하지 않음.

**선행 수행 구현 방법 — 권장안(미확정, Claude)**
- 현재 습관은 회차를 행으로 만들지 않고 공식으로 계산함. 그래서 **미래 회차를 미리 만들지 않아도** 다음 예정일을 계산해 선택지로 보여줄 수 있음(현재 `habitNextDueAfter` 계산 재사용 가능).
- 흐름: 금요일에 "수행 기록 추가" → 선택지 [지금 활성 회차(밀린 회차가 있으면 그것)] / [바로 다음 예정 회차(토요일)] / [예정 외 추가 수행] → 토요일을 고르면 `done_date=금요일, scheduled_date=토요일`로 저장.
- 토요일이 되면 그 회차는 이미 달성 기록이 있으므로 "오늘 할 습관"으로 뜨지 않음. 자동 건너뛰기 대상도 아님.
- 선택지 범위는 **활성 회차 + 바로 다음 회차 1개까지**로 제한 권장.

### 10-2. 건너뛴 회차의 사후 수행 — 권장안(미확정, 지피티 2차)
- 사용자가 건너뛴 회차를 **명시적으로 골라** 수행 기록을 추가하면 그 회차 상태를 완료로 바꿈. 수동/자동 건너뛰기 모두 같은 원칙.
  - **확정(4-A):** 건너뛴 회차의 메뉴에서 "수행 기록 추가"를 누르면 그 회차가 대상 — 회차 선택을 다시 묻지 않음. 완료되면 ×가 완료 표시로 바뀜.
- 과거 건너뛰기 이력은 보존.
- 이미 만들어진 다음 회차를 중복 생성하거나, 기존 반복 일정을 실제 수행일 기준으로 임의 변경하지 않음.

### 10-3. 추가 수행 — 권장안(미확정, 지피티 2차)
- 이미 완료한 회차에 추가 수행 기록을 남길 수 있음. 예정 외 추가 수행도 기록할 수 있음.
- 추가 수행은 **실제 수행 횟수에는 반영**하되, 예정 회차 달성률의 분자나 분모를 늘리지 않음.
- 같은 날에도 명시적인 "추가 수행 기록"은 허용 → 이전 "날짜당 기록 1개" 설계(6장)를 대체.
- 중복 클릭/저장으로 생긴 중복 기록과 의도적 추가 수행은 구분(구조는 9-C `kind` 참고).

### 10-4. 수정 범위 (습관 기준) — 지피티 2차
| 수정 항목 | 적용 범위 | 상태 |
|---|---|---|
| 제목·그룹 | 습관 전체에 적용한다고 안내하며 수정 | 권장안(미확정) |
| 시간 | **"이번 및 이후"만** | **확정(9-A)** |
| 반복 주기·요일 | "이번 및 이후"에 적용. 이미 완료되거나 건너뛴 과거 회차는 보존 | 권장안(미확정) |
- 과거 수행일과 완료 상태 등 실제 수행 기록은 바꾸지 않음.
- 습관의 이번 회차 예정일을 다른 날로 옮기는 기능은 제공하지 않음.
- 반복 할일의 날짜 이동 규칙(3장)은 습관과 구분.

### 10-5. 삭제 용어 재검토 — 권장안(미확정, 지피티 2차)
- 습관의 "이번 회차 삭제"는 건너뛰기와 기능이 겹치고, 달성률 분모에서도 회차가 사라질 수 있음 → 습관에는 두지 않는 방향.
- 일반적인 미실천 처리는 "이번 건너뛰기"를 사용.
- "이후 반복 종료"는 과거 수행 기록을 유지 → **9-B로 확정.**
- 잘못 생성된 회차의 삭제와 습관 전체 삭제 정책 → 10-6 E 권장안 참고.

### 10-6. B~G 권장안 (미확정, 지피티 3차 2026-09-24)

**B. 집 화면 체크**
- 표시된 회차의 체크 버튼을 누르면 그 회차를 선택한 것으로 본다.
- 회차 선택 확인 없이 완료하고, 실제 수행일은 **오늘**로 기록한다.
- 과거 수행을 뒤늦게 입력하는 경우는 "수행 기록 추가"를 이용한다.
- 날짜를 직접 선택했다는 이유만으로 항상 확인 창을 띄우지 않는다. 대상 회차가 명확하지 않을 때만 회차 선택을 요청한다.
- 다음 반복일이 오면 이전 미완료 습관은 자동 건너뛰고 새 회차를 표시한다.
- 오래 열린 화면에서도 체크 전에 회차 상태를 검증한다. 회차가 바뀌었다면 화면을 갱신하고, 클릭을 다른 회차에 조용히 적용하지 않는다.

**C. 선행 수행 후 반복 규칙 변경**
- 이미 수행 기록이 연결된 회차는 반복 변경으로 삭제하지 않는다.
- 원래 예정일, 실제 수행일, 완료 연결을 보존한다.
- 새 반복 규칙은 변경 대상인 미완료 예정 회차부터 적용한다.
- 보존된 선행 완료 회차와 새 규칙의 회차가 같은 날짜에 겹치면 중복 생성하지 않는다.
- 서로 다른 날짜의 수행을 임의로 다른 회차에 재연결하지 않는다.

**D. 습관 시간 수정** → **9-A로 확정.** (첫 버전은 "이번 및 이후"만, 과거 회차 불변, 회차별 시간 예외 저장 제외)

**E. 습관 종료 및 삭제**
- (9-B 확정 부분) 종료하면 앞으로의 반복을 중단하고, 기존 수행 기록과 과거 회차는 유지. 기록까지 지우는 삭제를 그대로 쓰지 않음.
- (권장안) 일반 메뉴의 "삭제"를 "습관 종료"로 바꾸는 안을 검토.
- (권장안) 종료하면 활성 목록 표시도 중단.
- (권장안) 종료 시 아직 수행하지 않은 미래 예정 회차는 취소하며, 미실천이나 달성률 분모로 집계하지 않음.
- (권장안) "기록까지 완전 삭제"는 별도 관리 화면에서 제공하고, 삭제 범위를 명시한 확인을 받음.
- (권장안) 현재 삭제가 기록까지 지우는 동작이라면 UI 이름만 바꾸지 말고 실제 삭제 관계와 동작을 먼저 확인 → **확인 결과: 기록까지 지움(9-B 참고).**
- (권장안) 잘못 생성된 회차 삭제는 일반 건너뛰기와 분리. 수행 기록이 연결된 회차는 기록을 조용히 함께 삭제하지 않음.
- (권장안) 자동 생성 오류를 사용자가 매번 정리하도록 하지 말고, 중복 생성 원인도 함께 수정.

**F. 기존 수행 기록 이관**
- 원래 예정 회차를 확실히 알 수 없는 기존 기록은 추측으로 연결하지 않는다.
- 수행일 등 기존 정보는 그대로 보존하고 회차 연결은 비워 둔다.
- 기존 기록은 달력과 실제 수행 횟수에 계속 반영한다.
- 새 회차 기반 달성률의 분자·분모에는 넣지 않는다.
- 화면에 "회차 달성률은 적용 시작일 이후부터 집계"라고 안내한다.
- 회차 연결이 없다는 이유로 기존 기록을 미실천 처리하지 않는다.

**G. 반복 할일 수정 및 삭제**
- 오늘 하기 / 내일 하기: 이번 회차 예정일만 이동. 반복 규칙 자체는 변경하지 않는다(3장 확정과 같음).
- 제목·그룹·프로젝트·날짜·시간의 상세 수정: "이번만 / 이번 및 이후" 선택.
- 반복 규칙 수정: "이번 및 이후" 적용.
- 과거 완료 기록은 수정 범위에서 제외.
- 일반적인 회차 생략은 "이번 건너뛰기"로 처리.
- "이후 반복 종료"는 다음 회차 생성을 중단하고 과거 기록을 보존.
- 완전 삭제는 건너뛰기·반복 종료와 분리하여 범위를 확인.

### 10-7. B~G 검토 결과 — 현재 구조 대조 (Claude, 2026-09-24)

**현재 구조로 가능한 것**
- B: 표시된 회차 체크 = 그 회차 완료(현재도 확인 없이 바로 기록). 다음 반복일이 오면 이전 회차는 화면에서 빠지고 새 회차 표시(현재 계산 방식이 이미 그렇게 동작). 체크 직전 재검증은 기존 계산 함수를 다시 호출하는 것으로 가능.
- D(9-A): 습관은 시간 1개만 저장하고, 과거 완료 기록은 체크 당시 시간을 따로 갖고 있어서 그대로 가능.
- E(9-B): 이미 있는 `end_date` 종료 상태가 "기록 보존 + 이후 중단 + 통계는 종료일까지"로 동작. 미래 회차는 행으로 존재하지 않아 "취소"할 대상이 따로 없음(계산에서 빠지기만 하면 됨).
- G: "이후 반복 종료"(현재 회차 행의 `end_date`/반복 해제), 체인 전체 완전 삭제(`repeat_chain_id` 기준)는 현재 컬럼으로 가능. 반복 할일은 다음 회차가 현재 행을 복사해 만들어지므로 "이번 및 이후" 수정은 현재 행 수정만으로 성립.

**구조 변경이 필요한 것**
- B·C·F 공통: 수행 기록에 "어느 회차 달성인지"(`scheduled_date`) 저장 칸(9-C).
- F: "적용 시작일"을 어딘가에 저장해야 "그 이후부터 집계"가 가능.
- C: 새 규칙에 없는 날짜에 연결된 보존 회차를 통계·달력에서 회차로 인정하려면, "계산된 회차 + 기록에 연결된 회차"를 합쳐서 보는 로직 필요.
- E: 일반 메뉴 삭제 동작 교체, 완전 삭제용 별도 관리 화면.
- G: 반복 할일 "이번만" 수정 — 다음 회차가 현재 행을 복사해 만들어지므로, "이번만" 바꾼 제목·시간 등이 다음 회차로 넘어가지 않게 하려면 **반복 원본 값(템플릿)을 따로 저장**해야 함. 할일 "이번 건너뛰기"도 회차 상태(건너뜀)를 저장할 칸이 필요.

**남아 있는 실제 충돌**
1. **B vs 현재 집 화면 체크:** 집 화면은 날짜 열이 여러 개이고, 체크하면 "오늘"이 아니라 **그 열의 날짜**로 기록됨. 미래 날짜 열에서 체크하면 미래 날짜 수행 기록이 생김 → B("실제 수행일은 오늘")와 10-1("미래 날짜 기록 불가") 둘 다와 충돌. 과거 열 체크를 막을지 허용할지도 정해야 함.
2. **B vs 10-1:** 10-1은 "예정과 다른 날짜면 회차 확인", B는 "대상 회차가 명확하지 않을 때만 확인". 둘 다 권장안이고, **"명확하지 않다"의 기준이 정의되지 않음.**
3. **F vs 7-1 확정(못 한 회차 = 연한 빨강):** 적용 시작일 **이전** 기간 달력에서, 계산상 예정일인데 수행 기록이 없는 날을 계속 빨강으로 보여줄지 정해야 함. F는 "미실천 처리하지 않는다"고 하고, 7-1은 못 한 회차를 빨강으로 표시함.
4. **G vs 8장 확정(프로젝트가 그룹을 정함):** G는 할일의 그룹을 "이번만 / 이번 및 이후"로 바꿀 수 있게 하지만, 프로젝트에 속한 할일의 그룹은 프로젝트를 따라가야 함. 프로젝트 할일에서 그룹 수정 칸을 어떻게 처리할지 정해야 함.
5. **G vs 2장 메뉴:** G는 할일에 "이번 건너뛰기"를 두지만, 2장 할일 메뉴(오늘/내일/집중/상세 수정/삭제)에는 건너뛰기가 없음.
6. **G — 반복 할일 다음 날짜 계산 → 늦은 완료 정책 확정 (2026-09-24)**
   - 현재 구현(사실 기록, `f5fb97f` 기준): 반복 할일은 "완료일 기준"이 **아님.** 모든 반복 단위가 **그 회차의 예정일(`start_date`) 기준**으로 다음 날짜를 한 번만 계산함(요일 지정 반복: 예정일 다음에 오는 지정 요일 / 일·주·월 간격: 예정일 + 간격). 그래서 늦게 완료하면 다음 회차가 이미 지난 날짜로 생김(예: 매일 반복 9/1 예정 → 9/5 완료 → 다음 9/2).
   - **확정 정책: 반복 할일의 늦은 완료 처리**
     - 다음 회차는 **완료일 이후의 첫 예정일**로 생성한다.
     - 이번 회차의 날짜를 이동했어도 **원래 예정일 기준의 반복 주기**를 유지한다.
     - 완료일 + 간격으로 주기를 재설정하지 않는다.
     - 중간에 지나간 회차는 생성하지 않으며, 완료 처리하지도 않는다.
     - 다음 회차는 **1개만** 생성한다.
     - 다음 예정일이 반복 종료일을 넘으면 생성하지 않는다.
   - 확정 예시:
     - 매일 반복: 9/1 예정 → 9/5 완료 → 다음 9/6.
     - 3일 간격: 9/1 예정 → 9/5 완료 → 다음 9/7.
     - 매주 월요일: 수요일에 늦게 완료 → 다음 월요일.
   - 구현 시 주의(지피티 검토 메모, 정책 아님):
     - `nextRepeatDateStr`는 할일·습관·일정 공용 함수 → 늦은 완료 정책은 **반복 할일 호출부에만** 적용하고 공용 함수 동작은 바꾸지 않음.
     - 원래 예정일 보존(3장)과 재체크 시 다음 회차 중복 방지(충돌 7)를 함께 고려.
     - 월 반복의 짧은 달 날짜 보정(말일 보정) 정책을 이 수정으로 조용히 바꾸지 않음.
   - 이 정책의 범위 밖(미확정 유지): 완료일이 원래 예정일보다 **이른** 경우(선행 완료)의 다음 날짜. 선행 완료 정책은 확정하지 않았음.
7. **E — 할일 중복 생성 원인 (현재 구현 확인 결과):** 반복 할일을 체크 → 다음 회차 생성, 체크 해제해도 생성된 다음 회차는 남아 있음, 다시 체크하면 **다음 회차가 하나 더 생김.** E의 "중복 생성 원인도 함께 수정"에 해당하는 실제 원인. (습관은 회차를 행으로 만들지 않아 이 문제가 없음)
8. **참고(현재 동작):** 습관 반복 규칙을 바꾸면(`cycle_changed_at`) 바꾼 날 자체가 새 기준 회차가 되는데, 요일 지정 반복이면 그날이 지정 요일이 아니어도 회차로 계산됨. C의 "새 규칙은 미완료 예정 회차부터 적용"을 구현할 때 함께 정리해야 함.

**코드 대조 메모 (2026-09-24, `f5fb97f` 기준, 지피티 확인 내용과 교차 확인)**
- `completeTodoRepeatIfNeeded`: 현재 예정일(`start_date`)에서 다음 날짜를 한 번 계산하고, 함수 안에 기존 다음 회차 확인이 없음(충돌 7의 원인).
- `habitDoneSinceOccurrence` / `habitOverallStats`: `done_date >= occDate`만 확인해서 수행 기록 하나가 여러 과거 회차를 완료한 것으로 집계될 수 있음(7-4).
- `toggleHabitForDate`: 전달받은 날짜(집 화면에서는 그 열의 날짜)로 저장하고, 체크 해제 시 그 습관·그 날짜 기록을 조건으로 삭제함. 지금은 DB 제약으로 날짜당 1개라 실제로 지워지는 건 최대 1개지만, 같은 날 여러 번 수행을 허용하면 기록별 해제 정책이 필요함.
