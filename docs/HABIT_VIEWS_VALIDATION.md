# 습관 공통 보기

기준 main: `965c8d4401d8bce9e46737b8794c5dec1446289f`. 기존 작업 폴더의 미커밋 변경은 유지하고 별도 작업 체크아웃의 `codex/habit-views`에서 구현했다.

## 데이터와 회차

| 구분 | 기존 저장 필드 | 새 보기에서의 의미 |
|---|---|---|
| 습관 원본 | `tok_habits.id` | 목록·보드 한 카드의 식별자, 관리·프로젝트·분류 연결 유지 |
| 반복 범위 | `start_date`, `end_date`, 반복 규칙·`cycle_changed_at`, 보관/재개 이력 | 기존 반복 함수 재사용. 새 달력 표시에서는 반복 종료일과 보관 구간도 제한 |
| 기준 회차 기간 | `occurrence_start_date`, `occurrence_end_date`, `all_day`, `start_minute`, `end_time`, `duration_minutes` | `OnekanPeriod`와 `habitPeriodRow`로 회차 날짜에 이동. 종일 끝 날짜 포함, 시간 종료 시점 제외 |
| 완료 기록 | `tok_habit_logs.id`, `habit_id`, `done_date`, 당시 `start_minute`·`duration_minutes`·`occurrence_end_date` | 수행 날짜와 당시 기간을 읽음. 현재 원본 기간으로 대체하지 않음 |
| 건너뜀 | `tok_habit_skips.habit_id`, `skip_date` | 실제 기록 날짜의 표시·취소. 시간 스냅샷이 없으므로 현재 시간을 과거 기록으로 추정하지 않음 |

달력의 임시 식별자는 원본 ID + 표시 종류 + 기준/실제 날짜다. 자정을 넘는 같은 예정 회차의 모든 구간은 같은 기준 날짜로 상태를 저장한다. 완료·건너뜀·취소는 기존 `setHabitDayStatus`를 사용하고, 저장 중 같은 키의 중복 실행을 막는다. 계정 변경 후 이전 요청이 새 계정의 메모리 기록을 갱신하지 않게 보호했다.

`done_date`를 예정 날짜로 재해석하지 않는다. 지연 수행은 오늘의 밀린 습관 안내에서 실제 수행일인 오늘로 기록한다. 예정 날짜와 이후 수행 기록의 회차 관계를 확정할 수 없는 이전 자료는 각각 표시하고 연결 미확정임을 알린다. 지난 예정일마다 밀린 카드가 늘어나지 않으며 밀림 안내는 기존 계산 결과를 원본당 하나로 표시한다. 과거 주기 변경·재개 이전의 예정일은 최신 규칙으로 복원하지 않는다. 실제 저장된 기록은 그대로 읽는다.

## 보기와 조작

- 첫 보기는 진행중 목록. 마지막 보기·달력 날짜/기간/시간 표시·회차 표시 필터·정렬·그룹화·보드 열 기준·진행 상태를 사용자별로 기억한다.
- 목록·보드는 진행중/보관/종료 상태별 원본 관리 화면. 정렬은 다음 예정일/이름, 그룹화는 없음/그룹/범주/프로젝트. 보드에는 미지정 및 빈 열을 포함한다.
- 달력은 1일/4일/한달, 타임라인/시간블럭, 종일/시간 구분, 겹침 배치와 날짜별 구간을 공통 엔진으로 처리한다. 미래 회차는 예측 표시이며 조회만으로 저장하지 않는다.
- 그룹 선택은 모든 보기의 조회 대상, 눈 설정은 달력에만 적용한다. 미지정 눈 설정과 모바일 그룹·범주 관리도 유지한다.
- 빈 공간의 범위 드래그는 저장하지 않고 추가창으로 전달한다. 종일 범위 종료일이 반복 종료일을 채우지 않는다. 블럭 추가는 시간 구간을 제안한다. Escape·무효 드롭 취소와 모바일 터치 스크롤을 보존한다.
- 기존 회차의 본체 이동과 종료 조절 저장은 지원하지 않는다. 종료 핸들을 노출하지 않고 이동 시 원본 수정창으로 연결한다. 수정창에 원본/앞으로의 회차 변경 안내를 표시한다.
- 기존 기록·원본 관리·보관/재개·종료·분류·프로젝트·지금한칸·공유 흐름을 재사용한다. 일정·할일은 기존 어댑터를 계속 사용한다.
