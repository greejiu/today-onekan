## 기준과 저장 구조

최신 main `4abc358ee519b5c96d7300db6af73e9265b4cb5d`에서 기존 관리 worktree의 `codex/todo-views`를 시작했다. 원래 프로젝트 폴더의 `codex/desktop-sidebar` 미커밋·미추적 변경과 암호화 복구본은 보존했다. 저장소 지침 CODEX_HANDOFF 및 실제 일정 보기, 공통 기간, 분류, 완료·반복, 언젠가 이동 코드를 확인했다. 저장소에서 AGENTS.md는 발견하지 않았다.

연결된 운영 프로젝트 `mmpsyajgyufdxmmnxqba`의 tok_todos 컬럼과 tok_todos/tok_someday 소유 RLS를 읽기 전용으로 대조했다. 새 테이블·컬럼·RPC·권한·마이그레이션은 없다. 운영 데이터에 대한 테스트 쓰기는 없다.

| 의미 | 기존 할일 필드 |
| --- | --- |
| 한 회차 시작·종료 | start_date/todo_time, occurrence_end_date/end_time |

일정의 event_date/category_id로 할일을 변환하지 않는다. 모든 배치는 tok_todos 원본 ID를 유지하며 날짜·시간블럭마다 새 행을 만들지 않는다. 언젠가는 tok_someday와 기존 이동 RPC를 그대로 사용한다. 기간 UPDATE는 tok_todos의 ID와 현재 user_id로 제한하고 반환 행이 없으면 실패한다. 기존 소유 RLS와 기간·분류 검증 트리거를 그대로 사용한다. Supabase의 기존 update/select/single 흐름을 공식 update 문서와 대조했다. changelog.md는 웹 도구의 text/markdown 제한으로 읽지 못했으며 새 SDK 기능이나 버전 변경은 없다.

## 변경 파일과 공통 규칙

- assets/item-views.js: 기존 일정의 겹침 열 계산, 시간축/블럭, 목록·보드, 상태, 범위 제안, 기간 이동·종료 조절, 저장 중복 방지·실패 복원을 공통 엔진으로 분리했다. 종류/페이지/테이블/DOM/필터/완료/연결 표시/월간 renderer는 어댑터로 전달한다.
- assets/schedule-views.js: 기존 일정 public 진입점과 geometry 테스트 API를 유지하는 얇은 어댑터다. 일정 월간 띠·상세·월 선택기는 그대로 index.html에서 사용한다.
- assets/todo-views.js: 할일 전용 어댑터, 월간 보기, 완료 체크·공통 메뉴·기존 수정창, 날짜 없는 항목 안내, 별도 언젠가 전환을 연결한다.
- assets/classification.js: 사용자·종류별 기존 눈 설정에 할일/미지정을 연결한다. 그룹 선택은 모든 보기 조회, 눈은 달력에만 적용한다.
- assets/schedule-views.css, index.html: 기존 CSS/테마/760px·하단바를 유지하고 할일 controls·공통 사이드바·추가창을 연결한다. 월간 칸 내부 스크롤과 모바일 가로 스크롤로 많은 항목에 접근한다. 메뉴 위에 드래그를 종료했을 때 pointerup과 클릭 억제가 제대로 처리되도록 공통 메뉴 위임을 연결했다. 숨겨진 탐색 포커스 복원을 보완했다.
- tests/todo-views.cjs: 새 보기·반복·기간·실제 포인터 조작 검증. 기존 transport fixtures와 관련 탐색/분류/프로젝트/일정 테스트는 공통 자산과 새로운 DOM 선택자에 맞춰 수정했다. 프로젝트명 별도 표시와 이름 수정 반영도 검증한다.

최초 목록, 미완료 필터, 날짜 없음 포함, 날짜별 그룹화/시작순 정렬, 그룹별 보드가 기본이다. 마지막 달력/목록/보드, 달력 기간/시간 표시, 정렬/그룹화/열 기준, 완료 필터, 날짜 없음 옵션, 기준 날짜·조회 기간은 `tok_todos_views:<user>`로 저장한다. 계정 변경 시 분리한다. 보기별 스크롤은 앱 사용 중 복원한다. 전체 메뉴 복원은 본문을 다시 그리지 않는다. 언젠가 작성 중 입력 및 공통 추가·수정창 입력은 보기/폭 변경으로 지우지 않는다.

1일/4일/한달, 타임라인/시간블럭을 제공한다. 로컬 날짜·OnekanPeriod의 포함되는 종일 종료와 포함하지 않는 시간 종료를 사용한다. 다음 날 00:00 종료는 다음 날 칸에 표시하지 않는다. 목록·보드도 명시적인 기간과 겹치면 포함하며, 날짜 없는 실제 할일은 선택 옵션/날짜 없음 그룹/미지정 열로 접근한다. 달력 안내에서 목록으로 이동한다. 완료 필터는 세 보기에 동일하다. 목록은 없음/날짜/그룹/범주/프로젝트 그룹화, 보드는 그룹/범주/프로젝트와 미지정·빈 열을 제공한다. 분류 열 드래그와 수동 순서 변경은 추가하지 않았다.

빈 날짜 선택, 더블클릭/＋추가, 날짜·시각 범위 드래그는 기존 입력창에만 제안한다. 일반 항목 이동은 실제 기간·연결·완료 상태를 유지한다. 종료 조절과 시각 이동은 15분 스냅이고 조회는 저장된 09:07 같은 값을 반올림하지 않는다. Escape/영역 밖/잘못된 범위는 저장하지 않는다. 실패 시 원래 위치 유지, 저장 중 중복 방지, 터치 스크롤 제외, 드래그 없는 수정/날짜 메뉴와 키보드 경로를 제공한다. 종료 없는 기존 항목은 조회 가능하며 직접 드래그 저장을 막고 종료 입력을 요구하는 기존 수정창으로 연결한다.

반복은 실제 저장된 예정/완료 행만 표시한다. 예측 미래 회차를 만들지 않는다. 반복 직접 드래그는 저장하지 않고 수정창을 연다. 완료는 기존 setTodoDone/다음 회차 생성/unique repeat_source_id 정책을 사용하고, 기존 회차의 예정 날짜·완료 기록을 다음 날짜로 바꾸지 않는다. 재체크는 기존 다음 행을 재사용한다.

## 적용과 배포 확인

DB 변경이 없어 DB 적용/복구 절차나 대기 migration 적용은 필요하지 않다. 이번 코드만 PR로 정책에 따라 병합한 뒤 기존 main 루트 GitHub Pages 배포를 사용한다. 배포 workflow 성공 후 실제 URL의 HTML과 함께 사용하는 8개 JS/CSS 자산을 로컬 검증본과 대조하고, 배포 URL에서 제공된 HTML을 격리된 인증/DB로 열어 주요 진입점·할일 모든 보기·모바일·기존 일정/비공개 방을 재검증한다. 별도로 실제 네트워크 익명 로그인 화면 HTTP 200/새 오류 없음/데이터 쓰기 없음도 확인한다. 배포 근거와 화면은 Git에 포함하지 않는 test-results에 남긴다.
