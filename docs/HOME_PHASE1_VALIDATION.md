# 집 3열 1단계 구현·검증 기록

기준: 최신 main `c7d147b`. 범위: `집_3열_타이머_공통메뉴_설계.md` 1·2·6장.

## 변경

- 집에 한정해 `언젠가 | 지금, 한칸 | 다가오는` 30:40:30 카드 배치. 기존 렌더 대상 ID와 항목 작업을 재사용한다.
- 1100px 이하에서는 가운데 카드를 먼저 보여주는 세로 배치. 웹의 가용 높이가 440px 미만일 때도 고정 높이를 해제한다.
- 상단 배너를 포함한 실제 위치에서 가용 높이를 계산하고 각 목록을 내부 스크롤한다. 날짜·보기 조작부는 목록 밖에 유지한다. 남은 할일과 그룹 칩도 과도하게 카드 높이를 차지하지 않는다.
- 가운데 날짜와 오른쪽 7일 범위 독립. 날짜 라벨은 키보드로 사용할 수 있는 초기 날짜 복귀 버튼이다.
- 마지막 보기(localStorage), 보기별 웹 목록 스크롤(sessionStorage)을 복원한다. 초기 렌더·재렌더 순서도 고려한다. 새 저장값이 없으면 기존 타임라인 기본값을 유지한다.
- 비동기 렌더는 마지막 호출만 반영한다. 기존 드롭 대상 날짜·시간을 유지하고 내부 가장자리 자동 스크롤, 타임라인 스크롤 이동량을 연결한다.
- 언젠가 정렬·그룹·5개 더 보기, PC 바닥 도착 후 쉬었다가 새 휠 입력으로 펼치는 규칙, 기존 항목 추가·체크·메뉴를 유지한다.
- 치즈 로고·파비콘·폰트·테마 관련 코드와 assets, DB/migrations는 변경하지 않았다.

## 검증 방법

`tests/home-layout.cjs`: Node.js + Playwright + Chrome. `playwright`가 Node 모듈 경로에 있어야 한다. 기본 Chrome 경로는 Windows 설치 경로이며 다른 환경에서는 `CHROME_PATH` 환경변수로 지정한다.

```text
node tests/home-layout.cjs
```

테스트는 HTML을 `http://onekan.test/`에 라우팅하고 Supabase 클라이언트를 메모리 모형으로 대체한다. 외부 요청은 전부 차단한다. 실제 운영 로그인·조회·쓰기·삭제·마이그레이션은 하지 않는다. 다른 탭의 비교 대상은 로컬 `origin/main:index.html`이다. 스크린샷은 git에서 제외한 `test-results/`에 생성한다.

## 검증 결과

- 1440×900, 1366×768: 세 카드 동시 표시, 하단 화면 내 배치, 가운데 넓은 비율, 가로 넘침 없음.
- 900×650, 720×450(확대 시 줄어드는 CSS viewport 대체), 390×844: 가운데 우선 세로 배치, 가로 넘침 없음.
- 1440×500: 낮은 화면의 고정 높이 해제.
- 날짜 독립 탐색·각 초기 날짜 복귀, 보기 전환·새로고침·재렌더 후 스크롤 복원 통과.
- 오른쪽·시간블럭의 지연 응답 역전 테스트 통과. 타임라인·하루종일에도 동일한 호출 버전 보호를 적용했다.
- 긴 제목, 32개 언젠가, 18개 그룹, 여러 날짜 항목, 남아 있는 할일 펼침, 두 배너 동시 표시 검증.
- 언젠가 바닥 도착만으로 추가되지 않고 새 휠 입력에서 5개 추가. 모바일 버튼으로 5개 추가.
- 언젠가·오른쪽 날짜·가운데 하루종일·시간블럭 드롭 좌표 판별, 포인터 정지 상태의 목록 가장자리 스크롤 검증.
- 실제 포인터로 가운데 할일을 오른쪽의 독립 탐색 날짜로 드래그한 뒤, 메모리 저장 데이터의 날짜가 일치하는지 확인했다.
- 390px 브라우저와 별도 터치 에뮬레이션에서 메뉴, 추가, 체크, 더 보기, 보기 전환 통과. 빈 하루종일 추가 입력도 확인.
- 일정·할일·습관·설정 탭의 모바일 문서 폭을 최신 main과 비교: 동일. JavaScript 오류 없음.
- 스크린샷으로 웹·모바일·빈 상태·배너 상태 확인. `git diff --check` 통과.

## 제한과 후속 작업

- 실제 휴대전화/Safari/Firefox, 실제 브라우저 줌 조작, 운영 DB 권한·네트워크 오류·동시 기기 저장은 미검증. 좁은 CSS viewport와 Chrome 터치 에뮬레이션이 실제 기기 검증을 대체하지는 않는다.
- 설정 화면은 390px에서 문서 폭 406px(16px 넘침). 동일 모형으로 최신 main에서도 재현되는 기존 문제이며 이 패치에서 변경하지 않았다.
- 기존 데이터 이동 위험: 언젠가↔할일 드래그의 insert/delete 원자성, 여러 날 일정의 종료일 소실, 습관 드래그의 공통 시간 변경. 이번 작업에서 해결했다고 보지 않는다. 타이머 연결 이전 별도 데이터 이동 안전성 작업이 필요하다.
- 타이머, 공통 메뉴 새 순서, 프로젝트, 통계 및 반복/기록 모델 개편은 후속 작업이다.
- main 병합·운영 배포는 이 작업에 포함하지 않는다.
