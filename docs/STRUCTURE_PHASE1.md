# 1차 구조 개편 — 메뉴 8개 · 작업(프로젝트) 탭 (2026-09-29)

## 무엇이 바뀌었나

- 메뉴: 지금 한칸(옛 '집') · 시간 추적 · 작업 · 일정 · 할일 · 습관 · 기록 · 설정.
  - PC 사이드바에 전부 표시. 모바일 하단은 지금 한칸·일정·할일·습관 + **더보기**(작업·시간 추적·기록·설정).
- '언젠가'의 화면 이름 → '담아두기'. 테이블(`tok_someday`)·동작은 그대로.
- 작업 탭: 정체성(선택) → 프로젝트 → 하위 프로젝트(선택, 2단계까지) → 할일·습관.
  - 프로젝트 생성·이름/설명 수정, 하위 프로젝트 생성, 정체성 등록·이름 수정·상위 프로젝트에 연결.
  - 기존 할일·습관 연결/해제(다른 프로젝트에 연결돼 있으면 옮길지 확인), 프로젝트 안에서 새 할일·습관 추가
    (기존 추가 창 재사용, 프로젝트만 미리 선택).
  - 항목은 복제하지 않음 — `project_id`로 같은 행을 가리켜 작업·할일·습관·지금 한칸이 같은 항목을 봄.
  - 할일·습관 추가/수정 창에 '프로젝트' 선택칸. 반복 할일의 다음 회차·복제본은 같은 프로젝트를 이어받음.
- 시간 추적: 현재 코드에 타이머가 없어 빈 상태 화면만(시작 버튼 없음).
- 기록: 날짜별 실제 기록(할일 완료일·습관 완료·습관 건너뛰기) + 기존 습관/반복 할일 기록 달력으로 가는 목록.
- 설정: 프로필 / 꾸미기 / 사용 설정으로 분류(새 설정 추가 없음).

## 하지 않은 것(후속 설계)

- 프로젝트 삭제·보관, 완료율, 자동 완료, 프로젝트↔그룹 연동, 정체성 대시보드·점수.
- 타이머 엔진·집중 모드·통계, 리포트, '오늘한칸 공유' 이미지 내보내기.
- 예시 데이터 자동 생성.

## 데이터(마이그레이션) — 운영 DB에는 아직 적용하지 않음

`supabase/migrations/20260929000000_tok_projects_identities.sql`

- 새 테이블 `tok_identities`, `tok_projects`(RLS: 본인 행만 select/insert/update, delete 정책 없음).
- `tok_todos.project_id`, `tok_habits.project_id` 추가(기존 행은 null = 미지정).
- 2단계 제한·자기 부모·순환 방지(트리거 + check), 다른 사용자 프로젝트 연결 불가(복합 외래키).
- 프로젝트가 지워져도 할일·습관·기록은 남고 연결만 풀림(`ON DELETE SET NULL`).

**적용 전에도 앱은 정상 동작한다.** 프로젝트 테이블을 못 읽으면 작업 탭에 안내만 보이고,
할일·습관 저장 시 `project_id`를 보내지 않는다.

### 적용 절차

1. Supabase 대시보드 SQL 편집기(또는 `supabase db push`)에서 위 마이그레이션 파일을 실행.
2. 앱 새로고침 → 작업 탭에서 '+ 프로젝트'가 보이는지 확인.
3. 프로젝트·하위 프로젝트 생성 → 새 할일 추가 → 할일 탭·지금 한칸에서 같은 항목이 보이는지 확인.

## 검증 범위

- 실제 DB: 마이그레이션을 되돌리는 트랜잭션 안에서 실행해 2단계 제한·자기 부모·순환·타 사용자 연결 차단,
  연결 해제·프로젝트 삭제 후 할일·습관·완료 기록 보존을 확인(적용 흔적 없음 확인).
- 브라우저(가짜 Supabase + Playwright): 완료 확인 1~8 흐름, 마이그레이션 전 상태, 390px 모바일.
- 미검증: 운영 DB 적용 후 실제 계정 흐름, 실제 휴대폰.
